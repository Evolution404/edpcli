# 原生 4Kn EDP 协议证据与写入门禁

日期：2026-10-09。实施环境：**仅 GitHub 源码与 Actions，Mac 离线**。

## 1. 基本原则

**已有来源无损重放**、**离线合成数据变换**、**官方原生4Kn新盘生产**及**真实设备写入认证**是四种不同的结论，不能互相替代。

- 厂商的512B写入端是现有协议生成金标；把512B投影放入每块4096B的前512B，只能形成兼容性假设和合成测试，不能证明厂家原生4Kn生产者如此编码。
- LBA0–12每个原生扇区的未知3584B以及LCE历史3072B负载之后的原生1024B，目前都必须原样保留，不猜测其归属或清零。
- 原生4096B的文件系统数据算法在离线软件路径上通过了官方驱动机器码密文金标；该证据不涵盖设备安全模块旁路、原生4Kn Windows挂载或设备级事务。
- `NativeEdpLayoutPlan::may_write()` 必须保持 `false`；应用层SMS4以外算法在准备与提交前均必须拒绝，原生4Kn设备写入另行拒绝。
- 不从 U391 进行任何实体写入；本阶段不开展密码检索。

## 3. 可在 GitHub 完成的工作

1. **统一只读来源接口**：由 `application::evidence::EvidenceSource` 的身份、容量、原生协议快照与扇区读取器共同调用严格重放接口，拒绝容量不符、错误块大小、快照漂移或缺失LCE；纯合成读源提供正负用例。
2. **覆盖离线组合矩阵**：四种布局 × 两种原生逻辑扇区宽度 × 三种已经证明的数据算法；物理明文区不能因协议 `NeedEncrypt` 标志就被当作密文，未知模式必须拒绝。
3. **保留厂家金标门禁**：已有官方驱动SHA金标用于*算法*而非新盘生产；未取得独立真实4Kn生产者金标不得将标识变为“写入认证通过”。
4. **远端全量 CI**：Rustfmt、非实体全量回归、Clippy、冗余审计、协议金标、全平台虚拟盘验收；全部通过才允许合并到开发分支。
5. **规范治理**：整理多次重复的进度批次编号，将当前状态入口与此证据矩阵互相引用；不提前将开发版合入 `main`。

## 4. 必须等待物理设备或额外官方证据的项目

- 独立的**厂家原生4Kn写入端输出**：至少提供LBA0–12完整块、LCE整块、分区起始/容量、密码封装模式的可核对真值及版本关联。
- Windows驱动/用户态的真实4096B挂载与文件系统读写；识别是否启用独立硬件安全模块及所选路由。
- 在明确授权的可牺牲测试盘上验证实际字节写入、写后回读、异常断开、掉电恢复与目标软件识别。**U391不作为测试写入对象。**
