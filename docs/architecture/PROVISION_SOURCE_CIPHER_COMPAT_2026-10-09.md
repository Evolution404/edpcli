# 制盘来源算法自动预填与算法兼容性（2026-10-09）

## 官方证据与当前边界

- LBA12 每条 EDPF 记录的偏移 `+0x58` 独立携带 `EncryptMode`：SMS4=2、AES=1、AES_CROSS=3。读盘端应依据每条加密记录解析，不得用 UI 默认值或另一分区代替。
- 当前逆向的官方量产写入端只有一个 `crypt` 参数：一次 `CreatePartitions` 把相同的算法模式写入该次创建的所有加密区域。**协议记录支持不同算法值，并不等于官方 GUI 已证明支持单次创建两区不同算法。**
- `ProvisionKeyProbe` 使用现有只读 512B/4096B 原生 EDPF 解析分别上报 Share、Encrypt 来源算法，映射与官方标签工具选项一致。不会读取本地 `.env`。

## 表单、预检与制盘防线

- 进入已注册盘的表单后，仅在来源解析证据到达、且用户没有手工改过目标算法时自动预填。两区相同选其算法；只有一区则选该区；两区不同时保留全局选择并提示冲突，绝不猜测双方均为 SMS4。
- 两个分区分别比较 `source_algorithm == target_algorithm`；来源未知不可宣称透传。算法不同则 **Passthrough/PreserveOpaque/PreserveVerified/RewrapVerified 均不可直接保留旧密文**，预检强制格式化重建；不能只重封 FileKey 来伪装数据层已切换算法。
- 应用层 `prepare_target_provision` 对来源实际 EDPF `EncryptMode` 和请求的全局目标模式再做独立检查，算法变化而没有明确格式化授权时拒绝请求，防止 TUI 以外的调用绕开。
- 此变更**不增加物理设备写盘权限**：AES/AES_CROSS 目标写盘仍被独立阻断，原生4Kn制盘仍须完成厂家生产者真值、文件系统与数据转换的实盘验证。当前真实 U391 始终只读。

## 回归验收

- Mode0 两区来源都为 AES_CROSS 时自动预填，目标改 SMS4 后两区均变为需重建，不再显示“透传”。
- Mode0 来源两区算法不同时，不伪装同一算法；全局目标变动后，重建判定跟随各自真实来源模式，不能同时无损保留两个不同算法区域。
- 来源算法探测尚未完成时保留密码验证进度，不在 UI 提前宣布成功透传；用户手动改目标算法后异步来源探测不会覆盖选择。
- 完整全量测试门禁 8 个套件、10 个产物，通过；仅证明模拟/只读读取链和静态写盘拦截，不代表实体制盘完成。
