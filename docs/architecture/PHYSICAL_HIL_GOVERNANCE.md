# 实体盘 HIL 治理

实体 USB 验收与虚拟磁盘 HIL 明确分离。虚拟 CI 用一次性 `loop`、`VHD` 或磁盘镜像验证各平台的 I/O 机制；实体盘结果用于证明某个明确场景已经在真实可移动介质上执行并完成读回验收。

统一场景清单位于 `audit/hil/physical_scenarios.tsv`。每个场景在 `macOS`、`Windows`、`Linux` 上使用相同的场景编号和预期语义。缺少所需实体硬件时可以把一次实际尝试记录为 `blocked`，但没有执行过的场景不是测试结果，严禁记录成 `pass`。

完成一次实体盘执行后，结果必须遵循 `audit/hil/physical_result.schema.json`。结果文件必须记录完整 40 位 Git 提交、平台与架构、物理介质几何、逐项断言以及带哈希的证据工件。只有所选场景的全部必需断言在写入和读回后均通过，才能记录 `status=pass`；已经执行但断言失败时记录 `fail`；因安全前置条件或硬件条件不足而无法继续的实际尝试记录 `blocked`。结果协议故意不提供 `not_run` 状态，避免把“未执行”伪装成验收结果。

基线包含六个发布关键场景：普通盘转 `mode0`、`mode0` 转 `mode1`、元数据恢复后执行 `FAT32` 格式化、元数据恢复后执行加密 `exFAT` 格式化、关键写盘期间请求退出、物理介质身份发生替换时拒绝继续写入。身份替换场景必须使用两块不同实体 USB，并证明检测到身份冲突后写入次数为零。

现有 macOS 实体盘证据继续保存在 `audit/protocol/notes/provision_lce_fat_hil_2026-10-01.md`；这些是历史真实证据，不会自动投影成 `Windows` 或 `Linux` 的通过结果。只有相应平台在真实可移动介质上执行对应场景后，才允许新增该平台的 `PASS` 记录。持续集成仍通过 `.github/workflows/virtual-disk-hil.yml` 提供非实体盘覆盖。
