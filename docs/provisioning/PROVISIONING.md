# 制盘当前规范

本文只描述当前代码已经实现的制盘能力。历史阶段计划、重构过程和交接记录由 Git 历史承担，不在本文件维护第二套状态。

## 1. 产品边界

edpcli 的制盘入口统一覆盖四种官方 EDP 模式和 Plain 普通盘目标。CLI 与 TUI 都通过应用层的制盘请求、只读准备和提交服务执行，不允许前端复制协议生成、裸盘写入或安全判断。

当前产品能力分为三类：

- `plan`：只读观察目标介质、解析已有布局并生成不可变计划，不卸载、不锁卷、不写扇区；
- `image`：把已经准备好的目标计划导出为与目标身份和几何绑定的稀疏镜像；
- `write`：经过完整介质授权和安全事务后写入真实物理盘。

Plain 不是 mode4。官方编号只有 mode0、mode1、mode2、mode3；Plain 是独立的普通 MBR 目标状态。

领域层 `src/provision/` 只处理纯内存模型、布局、密钥、区域保留/重建、文件系统镜像与写盘计划，不直接打开设备、执行系统命令或提权。真实设备访问和安全状态转换位于应用层。

## 2. 五种目标状态

| 目标 | 当前含义 | 典型逻辑区域 |
| --- | --- | --- |
| mode0 | 缺省三分区 | type1 启动区 + type2 交换区 + type4 保密区 |
| mode1 | 启动区和交换区二合一 | type2 二合一区 + type4 保密区 |
| mode2 | 整盘加密 | 兼容保留区 + type4 保密区 |
| mode3 | 内外网通用双分区 | type1 启动区 + type2 交换区 |
| Plain | 标准普通盘 | 1～4 个 MBR 主分区 |

代码中的统一目标类型是 `ProvisionTarget::{Plain, Official(...)}`，盘型投影使用 `DiskProvisionKind::{Plain, Mode0, Mode1, Mode2, Mode3}`。

官方模式默认从 LBA63 开始。mode0 启动区默认精确占用 20417 个 512B 扇区，因此后续区域从 LBA20480 开始。Plain 默认第一个分区从 LBA2048 开始并占满剩余空间；最多支持 4 个 MBR 主分区。

容量计算以 sector 为最终精确事实。人类可读容量单位统一由 `common::CAPACITY_UNIT_SYSTEM` 控制：`Decimal` 使用 MB/GB，`Binary` 使用 MiB/GiB。任何输入换算最终都必须落到扇区边界，并通过布局验证器检查重叠、越界、保留区冲突和目标容量。

## 3. 统一制盘流程

### 3.1 只读准备

制盘先固定目标介质并读取当前身份、容量、协议和分区信息，再构造 `ProvisionRequest`。准备阶段完成：

1. 识别目标是否为 Plain 或已注册 EDP；
2. 固定当前硬件身份、总扇区数和逻辑扇区大小；
3. 解析现有协议、分区和可复用密钥域；
4. 计算目标布局；
5. 计算各物理区域的处理方式；
6. 验证保留、密钥重新包装、重建和格式化授权是否收敛；
7. 生成不可变的写盘计划和格式化目标。

准备阶段不能改变目标盘。

### 3.2 制盘前元数据备份

真实 `write` 在任何破坏性写入之前强制创建 EDPB 元数据备份，并校验备份与准备阶段固定的目标身份一致。该备份与手工 `backup create` 使用相同的元数据语义。

备份失败、身份不一致或备份校验失败时，制盘不得进入卸载、锁卷和写盘阶段。

### 3.3 写盘提交

提交阶段经 `TargetSession` 完成只读状态到写入锁定状态的显式转换。随后按计划执行：

1. 再次确认目标为外接 USB 整盘且不是系统盘；
2. 卸载或锁定相关卷；
3. 重新打开设备；
4. 重新观察介质身份和精确几何；
5. 对所有将触碰的扇区先建立镜像；
6. 事务写入 LCE 与 LBA0～12 协议扇区，其中 MBR/LBA0 仍作为最后提交阶段；
7. 执行同步并对事务触碰的每个扇区做精确字节读回，任一不一致进入回滚；
8. 从最终 LBA7 重新解析 LCE 指针，重新读取连续 6 个扇区，以 zero8 和真实物理字节偏移解码，并与官方 3072B gold plaintext 比较；
9. 重新解析并验证 LBA0～12、onlyid 和最终分区几何；
10. 只有上述协议/LCE 验收全部通过后，才执行已授权的新文件系统格式化与格式化读回；
11. 任一失败按所属事务边界停止，写盘事务失败时执行回滚；
12. 成功后记录写后身份和备份关联信息。

用户确认不能跳过上述安全步骤。

## 4. 分区与文件系统

### 4.1 官方模式默认文件系统

当前第一方默认值：

- 启动区：FAT16；
- 交换区：exFAT；
- 保密区：exFAT。

`OfficialPartitionFilesystems::defaults()` 是当前默认事实源。

### 4.2 文件系统能力矩阵

文件系统领域使用统一 `FilesystemDriver` 接口。能力由驱动显式声明，不允许根据枚举名称推测。

| 文件系统 | 识别 | 读取元信息 | 第一方格式化 | 格式化读回 | 只读文件级分析 |
| --- | --- | --- | --- | --- | --- |
| FAT12 | 支持 | 支持 | 不支持 | 不支持 | 支持 |
| FAT16 | 支持 | 支持 | 支持 | 支持 | 支持 |
| FAT32 | 支持 | 支持 | 支持 | 支持 | 支持 |
| exFAT | 支持 | 支持 | 支持 | 支持 | 支持 |
| NTFS | 支持 | 支持 | 不支持 | 不支持 | 不支持 |

当前真实格式化和重建统一开放 FAT16/FAT32/exFAT；`filesystem::WRITABLE_FILESYSTEMS` 是 Provision、恢复后格式化、CLI/TUI 共用的可写格式真相源；`PROVISION_FILESYSTEMS` 仅保留兼容别名。FAT12 只补齐只读文件级分析，不作为制盘格式；NTFS 暂保持识别和元信息读取。只读分析能力不代表 Provision 会搬运用户文件。

### 4.3 Plain

Plain 使用 `PlainProvisionPlan` 和 `PlainPartitionSpec` 描述最多 4 个主分区。每个分区有显式起点、容量、文件系统和卷标；分区之间允许保留空闲区。

未显式指定分区时，默认生成从 LBA2048 到盘尾的单一 exFAT 分区。

## 5. 已有盘重制与数据保留

已有盘不是一律清空重建。当前代码先把源区域和目标区域建立类型化映射，再对每个区域选择处理方式：

- `PreserveOpaque`：无法解开但几何、加密和目标语义完全兼容时原样保留；
- `PreserveVerified`：已验证来源内容和目标完全兼容时保留；
- `RewrapVerified`：数据可保留，但目标密码策略变化，需要验证来源密码并重新包装密钥；
- `Rebuild`：不保留原内容，重建目标区域；
- `Drop`：目标模式不再需要该区域。

对普通用户文件系统区域，`Rebuild` 与“完整文件系统初始化”不可拆分：正常可执行计划不存在“重建但不格式化”。TUI 将交互状态明确区分为 `Preserve`、`RequiredRebuild`、`UserRequestedRebuild` 和不适用的固定协议区域；`RequiredRebuild` 自动启用并锁定格式化，而应用层仍保留 `Rebuild + format=false` 的 fail-closed 门禁。CLI 的显式格式化参数仍由命令行调用方负责提供，不能借 TUI 的交互归一化绕过应用层安全检查。

卷标遵循处理动作而不是表单默认值：`Preserve` 显示扫描到的来源卷标且只读，无法可靠读取时显示“未读取”；`Rebuild` 显示可编辑的格式化后卷标。默认启动/交换/保密卷标分别为“启动区/交换区/保密区”；mode1 二合一区复用交换区格式化开关，但默认目标卷标采用“启动区”。

### 5.1 文件数据边界

Provision 不提供文件级迁移。它不会为了模式转换或 Plain/EDP 转换而遍历目录、读取文件负载、暂存文件内容或把文件重新写入另一个目标文件系统。区域只能原地保留/重新包装密钥，或由用户明确授权重建；无法兼容且未授权重建时必须拒绝继续。

这一边界与备份恢复相互独立。备份和恢复使用 `metadata_only` 合约，只保存并恢复可恢复的分区/协议元数据，不保存或恢复用户文件。

### 5.2 mode0 到 mode1

mode0 重制为 mode1 时，计划器会根据现有布局决定保留、重新包装、重建或丢弃。对可兼容的 type4 保密区可以保持原起点、大小和密钥材料；启动区、交换区不能作为文件来源合并进新的二合一区。二合一区语义或几何需要变化时进入 `RequiredRebuild`；TUI 自动锁定必要格式化，原区域文件不会被复制。

### 5.3 Plain 与 EDP 之间

Plain 与官方模式之间不进行文件级转换。EDP→Plain 只清理/替换必要的 EDP 结构并建立新的普通分区和空文件系统，不需要来源密码，也不读取或迁移 EDP 文件；Plain→EDP 同样只按目标计划保留兼容区域或重建目标区域。确认页必须明确显示哪些区域会重建、哪些原文件不保留。

## 6. 密钥与密码域

官方 EDP 分区的密钥域由 `KeyDomainSecrets`、`SourcePasswordKnowledge` 和 `TargetPasswordPolicy` 共同描述。

来源密码状态分为：

- `DefaultVerified`：默认密码已验证；
- `UserVerified`：用户提供的密码已验证；
- `Unknown`：没有可验证密码。

当前默认密码为 `0000aaaa`。未知密码状态不能被当作默认密码成功。

当前规范写盘资料使用 `ProvisionProfile::canonical_v1()`，配置标识为 `jiangsu-safe6-v1`。默认 SAFE6 标签为“江苏电力!SAFE6”。

`PassInfoPolicy` 当前缺省值为：

- 初始化后不强制修改密码；
- 不取消密码复杂性检查；
- 交换区最大错误次数 255；
- 保密区最大错误次数 255。

如果现有注册盘的 LBA7/LBA12 密码策略能够可靠、且一致地解析，TUI/应用层可继承这些值；不可靠时使用显式默认值，不猜测。

`onlyid` 优先沿用扫描到的合法原值。只有源盘没有可靠值时才生成新的合法候选。

## 7. 写盘安全

以下条件属于不可绕过的安全门槛：

- 目标必须是可确认的外接 USB 整盘；
- 系统盘身份不能确认时拒绝写入；
- 准备阶段固定 selector、硬件身份和容量；
- 制盘前元数据备份必须完成并验证；
- 写前保护、卸载或锁卷必须成功；
- 重新打开后必须重新核对介质身份和几何；
- 真实写入只能由统一事务计划执行；
- 触碰扇区必须有镜像或等价回滚依据；
- 写后必须同步和读回；
- 回滚失败有独立错误结果，不能伪装成成功；
- 制造商 LBA3 的保留规则继续执行；
- 关键写入期间退出请求只能延迟到安全检查点处理。

这些门槛属于应用层/块设备事务边界，CLI 和 TUI 不得复制或弱化。

## 8. CLI 与 TUI

CLI 正式目标参数为：

```text
--target mode0|mode1|mode2|mode3|plain
```

CLI 使用 `--target mode0|mode1|mode2|mode3|plain`；`--mode` 已移除，不存在 mode4。

主要命令：

```text
edpcli provision plan ...
edpcli provision image ...
edpcli provision write ...
```

TUI 中必须先在设备列表固定目标盘，再按 `p` 打开制盘方案选择；`Enter` 在设备页用于打开设备详情，不再作为制盘快捷键。设备选择不属于 Provision 内部页面，制盘用户流程固定为：

```text
制盘配置 → 分区预览 → 计划确认 → 执行 → 完成
```

表单、计划和实际写入都复用应用层同一个准备结果。执行阶段与备份、恢复共用 `OperationRunState` 进度契约；总体百分比、逻辑阶段 `N/M` 和当前扇区工作量是三个独立维度。

## 9. 验证

常规修改至少运行：

```text
cargo fmt --all
git diff --check
scripts/test-fast.sh
```

大范围架构、写盘、安全链或发布前变更运行：

```text
python3 scripts/test-full.py --profile full
```

只有真实块设备事务、恢复或制盘后端语义发生变化时，才需要追加对应 Virtual Disk HIL 或实体 USB HIL。纯 UI、文档或事件投影修改不得把 HIL 结果伪装成新的写盘验证。

长期产品规范只记录当前能力和不可绕过的边界；真实样本、协议逆向过程和 HIL 记录放在 `audit/protocol/`。
