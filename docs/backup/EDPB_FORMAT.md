# EDPB 备份容器当前规范

EDPB 是 edpcli 当前唯一正式备份容器，扩展名为 `.edpb`。本文件描述现行容器、清单和恢复契约，不保存旧实施阶段日志。

## 1. 产品语义

当前备份只有一种：元数据备份。

备份保存：

- 物理介质身份和几何；
- 分区结构；
- Plain 盘所需的分区表原始元数据；
- EDP 盘的 LBA0～12、确认的 LCE 和已识别盘尾协议对象；
- 恢复所需的工件范围、完整性和来源关系。

备份不保存：

- 用户文件内容；
- 目录树；
- FAT、分配位图、MFT 等完整文件系统状态；
- “恢复后一定能立即挂载”的承诺。

因此元数据恢复成功表示分区/协议元数据事务成功并读回验证，不表示原文件系统或用户文件已经恢复。

## 2. 容器版本

外层二进制容器当前版本固定为：

```text
FORMAT_MAJOR = 1
FORMAT_MINOR = 0
HEADER_SIZE = 96
CHUNK_HEADER_SIZE = 64
FOOTER_SIZE = 80
```

当前新建元数据备份使用清单 `edpb.manifest.v3`，并声明：

```text
backup_purpose = metadata_only
capture_level = metadata
```

读取器只接受 `edpb.manifest.v3` 清单；支持 `core` 与 `metadata` 采集级别。v1/v2、`legacy_migrated` 和原始旧 `.bin/.md5/.sha256` 备份链不属于当前运行时输入。外层容器 1.0 与清单 v3 是独立版本，不能混淆；外层版本不表示支持旧清单。

## 3. 文件布局

固定整数使用小端序。文件顺序为：

1. 96B 固定头；
2. 一个或多个 64B 块头及块负载；
3. UTF-8 JSON 清单；
4. 80B 固定尾。

### 3.1 固定头

| 偏移 | 大小 | 含义 |
| --- | ---: | --- |
| 0x00 | 8 | 魔数 `EDPB\r\n\x1a\n` |
| 0x08 | 2 | 主版本 |
| 0x0A | 2 | 次版本 |
| 0x0C | 4 | 头长度 |
| 0x10 | 8 | 清单偏移 |
| 0x18 | 8 | 清单长度 |
| 0x20 | 8 | 固定尾偏移 |
| 0x28 | 8 | 采集时间戳 |
| 0x30 | 32 | 清单 SHA-256 |
| 0x50 | 16 | 保留区 |

### 3.2 块头

每个实体 `Artifact` 对应一个块。

| 偏移 | 大小 | 含义 |
| --- | ---: | --- |
| 0x00 | 8 | 魔数 `EDPCHNK\n` |
| 0x08 | 2 | 块版本 |
| 0x0A | 2 | 编码方式 |
| 0x0C | 4 | 保留 |
| 0x10 | 8 | 存储长度 |
| 0x18 | 8 | 原始长度 |
| 0x20 | 32 | 原始负载 SHA-256 |

当前写入器只写 `codec=none`。

### 3.3 固定尾

| 偏移 | 大小 | 含义 |
| --- | ---: | --- |
| 0x00 | 8 | 魔数 `EDPBFTR\n` |
| 0x08 | 2 | 主版本 |
| 0x0A | 2 | 次版本 |
| 0x0C | 4 | 保留 |
| 0x10 | 8 | 清单偏移 |
| 0x18 | 8 | 清单长度 |
| 0x20 | 8 | 完整文件大小 |
| 0x28 | 32 | 清单 SHA-256 |
| 0x48 | 8 | 保留 |

固定头和固定尾都保存清单定位和摘要，以便交叉校验。

## 4. 清单核心模型

### 4.1 快照

`SnapshotInfo` 保存快照标识、创建时间、采集级别和盘型状态。

### 4.2 身份

v3 `ManifestIdentity` 分为三部分：

- `hardware`：VID/PID、可用的 USB 序列号原文、厂商/产品/修订、传输方式和几何；
- `protocol`：`device_id`、`onlyid`、盘型和 LBA4 身份摘要；
- `derived`：兼容推导候选，不能替代强身份。

v3 在可用时保存 USB 序列号原文；拒绝 `hardware.serial_sha256` 字段和 `hardware_serial_sha256=` 授权备注。身份匹配与恢复授权只使用可用的原文，不使用历史摘要回退。运行时提权恢复 pin 的摘要是独立的当前安全机制。

系统临时盘号、备份文件名和容量相同都不是单独的恢复授权依据。

### 4.3 分区

`ManifestPartition` 保存：

- 分区索引；
- 逻辑角色；
- 分区类型；
- 精确起始 LBA；
- 精确扇区数；
- 可选文件系统提示；
- 可选卷标提示。

文件系统和卷标字段只是提示，不表示对应文件系统内容已被备份。

### 4.4 `Region`、`Extent`、`Artifact`

`Region` 表示有语义的逻辑区域。

`Extent` 表示实际物理范围，使用 `start_lba + sector_count`。

`Artifact` 表示真正写入 EDPB 的内容，并记录来源范围、派生关系、完整性、存储位置和 SHA-256。

恢复策略只有三种：

- `Restorable`：允许进入普通元数据恢复计划；
- `EvidenceOnly`：只保存证据，不自动写回；
- `DerivedOnly`：仅为派生结果，不能替代原始扇区写回。

## 5. v3 恢复契约

`RestoreContract::metadata_only(...)` 明确声明：

- 恢复分区结构；
- 对 EDP 盘恢复 EDP 协议；
- 不恢复文件系统；
- 不恢复用户数据；
- 恢复后必须进行只读评估。

非 v3 清单直接拒绝；每份 v3 必须具备类型化身份、`metadata_only` 目的与完整恢复契约。

备份工作区的“恢复范围”属于该契约的只读投影：容量地图描述清单声明的恢复后几何，区域状态再区分“原始字节完整可恢复”和“只恢复结构”。`RestoreContract` 是能力上限，不能因为清单中存在分区、文件系统提示或卷标提示就升级为“文件系统/用户数据可恢复”。缺失或部分采集的必需原始工件必须显示为不完整，而不是被结构信息掩盖。

## 6. Plain 采集范围

### 6.1 MBR

Plain MBR 保存原始 LBA0、经过验证的扩展分区 EBR 链以及类型化分区几何。EBR 链拒绝循环、越界和超过 128 个节点的输入。它不保存 EDP 固定协议区。

### 6.2 GPT

Plain GPT 保存：

- protective MBR；
- 主 GPT header；
- 主 entry array；
- 备份 entry array；
- 备份 GPT header。

采集时校验主备头部 CRC、分区数组 CRC、磁盘 GUID 和几何一致性。单份 GPT 分区数组最多 8MiB，分配前检查长度与容量。

### 6.3 文件系统提示

Plain 为生成 `filesystem_hint` 和 `volume_label_hint` 可以进行有界、瞬时、只读读取。此读取只用于提示，不创建新的可恢复文件系统 `Artifact`。

当前提示读取不能被解释成“目录或用户文件已备份”。

## 7. EDP 采集范围

EDP 元数据备份保存：

- 原始 LBA0～12，共 13 个扇区；
- LBA7 指针确认的 6 扇区 LCE；
- 已确认的盘尾历史镜像对象；
- 已确认的盘尾恢复节点；
- 类型化分区几何与身份。

LBA7/LBA12 中的 `PassInfo`、`NeedEncrypt`、`EncryptMode`、包装 FileKey 和 CRC 保存原始字节。创建备份不要求用户知道分区密码，也不需要解开 FileKey。

交换区/保密区卷标提示来自已经验证的协议字段，不为备份目的额外遍历加密分区文件系统。

## 8. LCE 与盘尾对象

LCE 位置以 LBA7 指针为事实源；CHS 只作一致性交叉验证。多个逻辑角色可以引用同一物理 LCE，但不能因此合并其逻辑语义。

盘尾只保存协议证据已经确认的对象。未知相邻空间仍然是未知空间，不得为了“完整”而推断成协议区域。

详细协议结论见 `docs/protocol/LCE.md` 和协议逆向总文档。

## 9. 完整性

读取和校验至少检查：

- 固定头/尾版本与长度；
- 清单位置和 SHA-256；
- 块边界；
- 块编码；
- 每个 `Artifact` 的 SHA-256；
- 存储范围不重叠；
- `Region → Extent → Artifact` 引用有效；
- v3 备份目的与恢复契约；
- Plain/EDP 各自要求的工件；
- 分区几何合法性。

可恢复工件还必须满足完整原始扇区、512B 对齐、已识别区域、获准的角色/用途和无重叠范围。读取器用工件原始字节重新解析 Plain 分区表，确认 MBR/EBR/GPT 元数据范围与清单几何对应；EDP 的 LCE 必须匹配 LBA7 指针，盘尾对象必须匹配已确认的角色、起点和长度。仅重算 SHA-256 不能把任意字节授权为可恢复元数据。

读写两端使用相同负载预算：单份容器最多 256MiB，清单最多 4MiB，工件最多 1024 个，单个工件最多 64MiB，总负载最多 128MiB。读取器在分配前检查声明长度；写入器在创建输出前验证工件预算。

EDPB 是自包含容器，不生成备份用 `.sha256` 旁挂文件。用户重命名 EDPB 文件不会改变容器内部的身份和完整性。

主备份页不直接展开 `Region / Extent / Artifact` 明细。经过容器验证后，备份检查页会保留同一份已验证清单，并在技术证据视图展示区域几何/语义状态、物理范围、工件恢复策略/完整性、`source_extent_ids` 和 SHA-256；这只是只读证据展示，不改变恢复授权。

## 10. 恢复安全

恢复只把 `restore_policy=restorable` 的原始工件转换为写盘事务。

恢复前必须：

1. 完整验证 EDPB；
2. 固定目标物理盘；
3. 验证强身份证据；
4. 验证逻辑扇区大小和总几何；
5. 卸载或锁定相关卷；
6. 重新打开后再次观察身份和盘面。

写盘使用统一事务、同步、读回和失败回滚。Plain v3 恢复到同一块仍残留旧 EDP 协议的介质时，可以执行目标侧归一化清理；这些清理字节不是备份内容。

## 11. 恢复后评估

元数据恢复完成后再进行独立只读评估，分区状态可以是：

- `Usable`；
- `NeedsFormat`；
- `PasswordRequired`；
- `CryptoMetadataInvalid`；
- `Unsupported`。

后续格式化或密钥域重建是新的授权操作，不属于“恢复已经成功”的必要条件。后处理失败不能反转已经通过读回验证的元数据恢复结果。

加密分区沿用原密钥域格式化前，必须验证密码、包装 FileKey 和 FileKeyCRC。重建加密分区还要求新密码双输入和独立破坏性确认。

## 12. 历史兼容边界

当前运行时不把旧 `.bin/.md5/.sha256` 备份链当作 EDPB，也不维护旧“深度备份”产品入口。

EDPB v1/v2 读取与摘要身份适配均已移除。旧文件应先归档，再离线转成 v3；转换只保留已采集的元数据，不补造 LCE、盘尾或文件系统内容。无法从可信现有记录找回原始 USB 序列号时应标记 `missing`，旧摘要可作为迁移来源记录，不能成为写入授权。EDP 物理盘协议的历史布局与密钥读取兼容继续保留。

协议和物理样本的历史证据保存在 `audit/protocol/`，不继续堆入本规范。

## 13. 文件发布与目录顺序

备份、制盘镜像和检查导出通过同目录私有候选文件写入，完成同步后发布。Unix 新建文件权限为 `0600`，新建目录为 `0700`；Windows 设置受保护访问控制。已有目录权限不会自动收紧。备份使用禁止覆盖的发布策略，镜像替换在成功发布前保留旧文件；发布后的目录持久化失败仍向调用方报告错误。

检查导出每次使用独立目录，全部工件成功后才原子发布 `complete.json`。缺少此标记表示导出尚未完成，不能把部分文件当作完整证据。

有效备份的排序与保留策略使用经过容器验证的采集时间。修改文件名或文件修改时间不会改变新旧优先级；无效或无法读取容器的修改时间只用于展示。展示目录扫描发生权限或读取错误时保留错误状态，不能伪装为空目录。恢复与删除仍重新校验具体容器，展示缓存不承担授权。
