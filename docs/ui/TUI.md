# TUI 当前交互规范

本文描述当前 ratatui 前端的真实交互和架构。历史视觉迁移、设备工作台计划和阶段性验收不在本文件保留。

## 1. 工作区与层级

TUI 的顶层只有两个用户工作区：

- 设备；
- 备份。

全盘检查和制盘是嵌套工作流，不是第三、第四个平级顶层标签。代码中 `Workspace::TOP_LEVEL` 只包含 `Devices` 与 `Backups`。

`AppState` 由全局 shell 状态和四个功能子状态组成。前端控制器统一解释生产模式与演示模式的 `TuiAction`；需要设备、文件或平台副作用的动作返回任务请求，由生产任务层执行。

`Esc` 返回当前层级，`q` 表示退出整个应用。关键写盘事务执行期间，退出请求延迟到安全检查点。

## 2. 键位

### 2.1 全局

| 键位 | 当前行为 |
| --- | --- |
| `j / k` | 当前控件上下移动 |
| `h / l` | 表格切换激活列；树折叠/展开；输入框内是普通字符 |
| `gg / G` | 当前列表或树首项/末项 |
| `Ctrl-d / Ctrl-u` | 半页移动 |
| `Tab / Shift-Tab` | 顶层设备/备份切换；嵌套页内切换本页焦点 |
| `gt / gT` | 下一个/上一个顶层标签 |
| `Ctrl-w h/j/k/l/w/W` | 当前功能页内部面板方向或循环切换 |
| `/` | 搜索 |
| `n / N` | 下一个/上一个匹配 |
| `?` | 帮助 |
| `Esc` | 返回或取消当前层级 |
| `q / Ctrl-C` | 发出全局退出意图 |

### 2.2 表格

统一表格语义：

- `j/k`：选行；
- `h/l`：上一列/下一列；
- `H/L`：平滑横向滚动；
- `</>`：移动整列顺序；
- `0/$`：首列/末列；
- `s`：当前列正序/倒序；
- `S`：恢复默认排序；
- `y/Y`：复制单元格/整行。

横向和纵向滚动条只在真实溢出时显示。

## 3. 设备工作区

设备页用于扫描、选择和查看当前 USB 介质。

主要动作：

- `Enter`：打开设备详情或进入详情焦点；
- `o`：在设备详情树展开/折叠；
- `i`：进入全盘检查；
- `p`：进入制盘方案选择；
- `b`：创建当前设备的元数据备份；
- `R`：在详情中存在已选关联备份时进入恢复。

设备页的 `Enter` 只负责设备详情；制盘入口固定为 `p`。

## 4. 备份工作区

备份页使用统一 EDPB 目录索引和全局稳定显示编号。

主要动作：

- `Enter / i`：检查选中备份；
- `b`：创建新元数据备份；
- `v`：校验；
- `R`：恢复；
- `d`：删除当前或已勾选备份；
- `Space`：勾选/取消勾选，用于批量删除。

### 4.1 创建备份

按 `b` 直接在当前工作区上覆盖一个确认 Modal。底层设备或备份页面保持可见，不切换成空白页面。

该确认说明：

- 只读取身份、几何、分区结构和适用的 EDP 协议元数据；
- 不向目标介质写入。

用户按一次 `Enter` 确认后直接进入 `Running`；不存在第二层“备份类型”选择，也不存在第二次 Enter 才真正开始的问题。

`Esc` 取消后保持原工作区、焦点和选择。

### 4.2 恢复

恢复是介质写入，仍要求精确输入 `YES`。创建备份的只读确认不能复用或削弱恢复确认。

恢复成功后进入类型化后处理状态，可根据分区评估分别进入卷标编辑、明文格式化、密码验证、加密格式化或加密分区重建。

## 5. 全盘检查

全盘检查只有一套实现，设备和备份都进入同一个浏览器。

主要 Pane：

1. 结构树；
2. 节点概览；
3. 节点详情。

磁盘布局按物理 LBA 顺序展示协议区、分区、LCE、已确认盘尾对象和未知区域。未知区域不能自动改名为空闲空间。

常用操作：

- `Tab/Shift-Tab`：循环本页 Pane；
- `o`：折叠/展开；
- `gl`：跳转 LBA 或绝对字节位置；
- `/`：搜索结构节点和已缓存字段；
- `n/N`：匹配间循环；
- `1/2/3/4`：切换业务字段、原始字段、十六进制、全盘布局视角；
- 扇区检查器用 `[/]` 切换前后扇区，`v` 循环原始/解码/混合视图。

LBA0～12 等已经缓存的节点在选中时直接更新概览和详情，不要求再次 Enter 才显示。

## 6. 制盘流程

从设备列表选中目标 USB 后按 `p` 打开制盘方案 Modal。设备选择属于进入制盘前的工作区上下文，制盘内部不再提供第二个“选择设备”页面；没有固定目标时不能直接进入 Provision 工作区。

用户可见阶段固定为：

```text
1 制盘配置
2 分区预览
3 计划确认
4 执行
5 完成
```

内部 `ProvisionStage` 还包含只读计划生成、镜像导出、确认和结果等细分状态，但这些内部状态不改变上面的用户步骤语义。

表单 Normal 模式用 `i` 编辑当前字段；输入状态中的方向键移动光标，Enter/Esc 结束字段编辑。配置完成后 Enter 生成只读计划。

真实写盘必须再次经过精确 `YES` 确认和应用层安全事务。

## 7. 长操作进度

备份创建、恢复和制盘共用 `OperationRunState`，不维护三个互不兼容的运行页。

进度被明确拆成三个维度：

- `OverallProgress`：整个操作的总体进度，使用 0～10000 基点；
- `StageProgress`：逻辑步骤序号，例如 `2/7`；
- `WorkProgress`：当前步骤内部的 sector/byte 工作量，例如 `11807 / 15661 sector · 75%`。

渲染规则：

- “总体进度”使用一行高 Gauge；
- “当前状态”显示 `N/M · 阶段名`、当前步骤和活动说明；
- 当前工作进度条同样只占一行，必须完全位于“当前状态”边框内部；
- 工作进度条不能覆盖或穿过下边框；
- 运行日志只记录语义事件，不为每一个 sector 生成日志行；
- 总体百分比由应用层事件生产者提供，渲染器不能自行猜测业务百分比。

`ProgressSpan` 用于把事务内部进度映射到总体进度区间。高频快照在运输层合并，警告、错误、回滚和阶段边界不会被丢弃。

正常终端刷新最短间隔为 50 ms，即上限约 20 Hz。存储层仍可产生更高频的扇区事件，但不会要求终端同频刷新。

共享页面由 `operation_progress_render.rs` 组织，当前状态卡片由 `operation_progress_status.rs` 独立负责，以保持布局职责边界。

### 7.1 统一结果汇报页

运行页负责展示“正在发生什么”，结果页只展示“最终得到了什么”。只有制盘、备份创建、恢复这类包含需要用户检查的结构化结果时才保留独立结果页，并统一使用 `ui/operation_result.rs`。单备份删除、批量删除和 keep-N 清理属于通知型操作：输入、规划和执行状态都作为备份列表上的模态覆盖层展示，计划完成后直接进入确认 Modal，执行结束立即回到备份列表并通过 Notice 汇报成功或失败，不再创建独立等待页、Review 页或 Result 页。

结果页不得继续复制运行日志或“最近进度事件”。制盘成功页优先展示：

- 最终盘型与总容量；
- 每个分区的角色、文件系统、起始 LBA、实际大小和最终状态；
- 分区结果下方使用与设备详情同源的全盘容量地图和区域列表；区域列表统一展示“区域 / LBA 范围 / 容量 / 占比”，并按完整新盘几何显示协议区、空闲区、分区、LCE 和折叠尾部区域；
- 协议、几何和格式化读回验收结果；
- 制盘前自动备份文件与总耗时。

制盘写入前只把无敏感信息的 `ProvisionResultSnapshot` 留给结果页；完整 `PreparedProvision` 仍移交后台写入任务，不为了结果展示在 TUI 中额外保留密钥材料副本。

总体和当前工作进度条使用同一套高对比度粗体标签样式，工作进度文字不能因为使用次级进度色而降低可读性。

## 8. 视觉与表格

TUI 统一使用主题模块提供的 24-bit TrueColor 低饱和配色，并保留 ANSI256/ANSI16 降级。

禁止各工作区自行硬编码私有高饱和颜色。分区、盘型、风险和焦点使用统一语义色。

当前焦点至少通过边框、标题或表面变化之一明确区分；选中行、激活列和 Pane 焦点是不同状态，不能只靠同一种反白效果表达。

所有交互表格复用统一列模型、显示宽度计算、复制规则、排序、列移动和滚动条逻辑。

## 9. 安全边界

TUI 是应用服务的前端，不直接拥有裸盘安全策略。

必须保持：

- 外部介质文本渲染前过滤终端控制字符；
- 后台 worker 不直接写 stdout/stderr；
- 同类后台任务使用单飞和代次保护；
- 真实写盘复用 CLI 相同的 `TargetSession` 和事务服务；
- 关键阶段内 `q`、`Esc`、`Ctrl-C` 只登记延迟退出；
- Modal 通过共享覆盖层绘制，不得清空其下方工作区；
- 全局底部状态/安全提示保持固定布局，不因局部页面进度变化发生跳动。

任何 TUI 改动如果改变真实写盘授权或事务语义，必须在应用层先完成对应设计和测试，不能只通过前端快捷键实现。
