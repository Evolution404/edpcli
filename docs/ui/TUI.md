# TUI 当前交互规范

本文描述当前 ratatui 前端的真实交互和架构。历史视觉迁移、设备工作台计划和阶段性验收不在本文件保留。

## 1. 工作区与层级

TUI 的顶层只有两个用户工作区：

- 设备；
- 备份。

全盘检查和制盘是嵌套工作流，不是第三、第四个平级顶层标签。代码中 `Workspace::TOP_LEVEL` 只包含 `Devices` 与 `Backups`。

`AppState` 由全局 shell 状态和设备、备份、检查、制盘、恢复五个功能子状态组成。前端控制器统一解释生产模式与演示模式的 `TuiAction`；需要设备、文件或平台副作用的动作返回任务请求，由生产任务层执行。

`Esc` 返回当前层级。Normal 模式下 `q` 或 `Ctrl-C` 表示退出整个应用；输入、搜索、命令和确认状态优先解释输入语义，其中 `q` 是普通字符，`Ctrl-C` 取消当前输入。关键写盘事务执行期间，退出请求延迟到安全检查点。

## 2. 键位

### 2.1 全局

| 键位 | 当前行为 |
| --- | --- |
| `j / k` | 当前控件上下移动 |
| `h / l` | 表格切换激活列；树折叠/展开；输入框内是普通字符 |
| `gg / G` | 当前列表或树首项/末项 |
| `Ctrl-d / Ctrl-u` | 半页移动 |
| `Tab / Shift-Tab` | 顶层设备/备份切换；嵌套页内切换本页焦点 |
| `Ctrl-w h/j/k/l/w/W` | 当前功能页内部面板方向或循环切换 |
| `/` | 搜索 |
| `n / N` | 下一个/上一个匹配 |
| `?` | 帮助 |
| `F2` | 查看最近消息的完整详情；再次按下关闭 |
| `Esc` | 返回或取消当前层级 |
| `q / Ctrl-C` | Normal 模式发出全局退出意图；输入状态下分别为字符 `q` / 取消输入 |

消息提示的摘要保留 `F2 详情` 入口。详情按终端显示宽度换行，支持 `j/k`、`PgUp/PgDn`、`gg/G` 滚动，`Esc/F2` 关闭；四秒提示消失后，最近消息仍可通过 `F2` 打开。打开的消息是固定快照，后台新通知不会覆盖正在阅读的详情。详情里的 Enter 和普通字符不会提交底层表单或写入确认，关键事务中的退出请求继续延迟到安全结束。

### 2.2 表格

统一表格语义：

- `j/k`：选行；
- `h/l`：上一列/下一列；
- `H/L`：平滑横向滚动；
- `</>`：移动整列顺序；
- `0/$`：首列/末列；
- `s`：当前列正序/倒序；
- `S`：恢复默认排序；
- `y/Y`：复制单元格/整行。

横向和纵向滚动条只在真实溢出时显示。

## 3. 设备工作区

设备页用于扫描、选择和查看当前 USB 介质。

主要动作：

- `Enter`：打开设备详情或进入详情焦点；
- `o`：在设备详情树展开/折叠；
- `i`：进入全盘检查；
- `p`：进入制盘方案选择；
- `b`：创建当前设备的元数据备份；
- `R`：在详情中存在已选关联备份时进入恢复。

设备页的 `Enter` 只负责设备详情；制盘入口固定为 `p`。

## 4. 备份工作区

备份页使用统一 EDPB 目录索引和全局稳定显示编号。主体由左侧“设备”导航树和右侧现有备份表组成；设备导航只是只读筛选，不改变备份的全局编号，也不获得删除、恢复等破坏性授权。

设备树默认选中“全部备份”，展开后列出具有强身份证据的设备，并额外提供“身份未确认”虚拟筛选节点。强身份的主证据只接受可用 USB 序列号，或 EDP `device_id + onlyid`；同时必须通过 VID:PID、精确总扇区数和逻辑扇区大小的一致性门禁。容量不是独立身份来源，但同一序列号若出现不同物理几何必须拆成不同设备组，并同步阻止 destructive prune 跨几何合并。型号、容量、VID:PID、文件名等弱字段本身不能用于把多份备份认定成同一设备。“身份未确认”只表示筛选集合，不能把其中条目视为同一台设备。

设备树交互：

- `j/k`：切换设备筛选，并立即刷新右侧表格；
- `gg/G`：首项“全部备份”/末项；
- `H/L`：按终端 cell 平滑左右滚动设备树；横向范围以当前激活设备的完整文本宽度为准，可滚到最右端查看完整身份和容量，不使用省略号替代隐藏内容；
- `o`：折叠/展开设备树；折叠不清除当前设备筛选；
- `Enter`：把焦点移入右侧备份表；
- 搜索和表格排序始终在当前设备筛选结果内执行，顺序为“设备筛选 → 搜索 → 表格排序”。

右侧备份表主要动作：

- `Enter / i`：检查选中备份；
- `b`：创建新元数据备份；
- `v`：校验；
- `R`：恢复；
- `d`：删除当前或已勾选备份；
- `Space`：勾选/取消勾选，用于批量删除。

备份页下方左侧为“备份元数据”，按健康与身份、基本信息、来源设备、归属信息、完整性与备份范围、文件与摘要的顺序显示；长文件名和 SHA-256 位于下部，可滚动查看。右侧独立的“容量布局”窗口复用设备页布局显示，提供区域名称、LBA 范围、扇区数、容量和占比。颜色表示状态及区域角色，未采集用户文件是产品范围，不作为失败。窄屏或低高度时显示当前焦点窗口，使用 `Ctrl-w w` 切换，列表、元数据与容量区域均可访问。

### 4.1 创建备份

按 `b` 直接在当前工作区上覆盖一个确认 Modal。底层设备或备份页面保持可见，不切换成空白页面。

该确认说明：

- 只读取身份、几何、分区结构和适用的 EDP 协议元数据；
- 不向目标介质写入。

用户按一次 `Enter` 确认后直接进入 `Running`；不存在第二层“备份类型”选择，也不存在第二次 Enter 才真正开始的问题。

`Esc` 取消后保持原工作区、焦点和选择。

### 4.2 恢复

恢复是介质写入，仍要求精确输入 `YES`。创建备份的只读确认不能复用或削弱恢复确认。

恢复成功后进入类型化后处理状态，可根据分区评估分别进入卷标编辑、明文格式化、密码验证、加密格式化或加密分区重建。

## 5. 全盘检查

全盘检查只有一套实现，设备和备份都进入同一个浏览器。

全盘检查固定采用“四层职责”：

1. **扇区树（位置）**：只负责磁盘区域、分区、扇区和字段的层级导航；
2. **对象摘要（结论）**：只给当前对象的名称、归属、状态和关键语义结论，不堆原始字节或校验过程；
3. **技术证据（依据）**：统一以结构化表格展示字段、几何、校验、解码、文件系统和备份清单证据；有已注册字段解析器时显示字段表，否则显示“类别 / 项目 / 值”证据表；
4. **字节检查（字节）**：独立的全宽 `Raw / Decode / Mixed` 十六进制检查区，不与对象摘要或技术证据混用。

顶部容量地图是全局上下文条，不是可聚焦 Pane。宽屏下扇区树位于左侧，对象摘要与技术证据位于右侧上下排列，字节检查横跨底部；紧凑尺寸只显示当前聚焦 Pane，避免把四个区域同时压窄。

字段表必须复用统一 `data_table + TableState + selection_overlay` 合同：Known/Unknown/Reserved/Preserved 等语义色只作用于 Status 单元格，普通 Offset/Field/Value/Raw/Decoded 等列使用统一表格文字色；选中行由连续背景表示，禁止逐 Cell 绘制导致列间断层，也禁止因选中或 Known 状态把整行变成 accent 蓝色。

磁盘布局按物理 LBA 顺序展示协议区、分区、LCE、已确认盘尾对象和未知区域。未知区域不能自动改名为空闲空间。

常用操作：

- `Tab/Shift-Tab`、`Ctrl-w w/W`：循环本页四个 Pane；
- `Ctrl-w h/j/k/l`：按空间关系在扇区树、对象摘要、技术证据、字节检查之间移动焦点；
- `o`：折叠/展开树节点或当前字段详情；
- `J`：在检查浏览器任意窗口直接打开 LBA 跳转；
- `/`：搜索结构节点和已缓存字段；
- `n/N`：匹配间循环；
- 字节检查器用 `[/]` 切换前后扇区，`v` 循环 Raw/Decode/Mixed，`h/l` 按 byte 移动，`j/k` 按 16B 行移动。

LBA0～12 等已经缓存的节点在选中时直接更新对象摘要和技术证据，不要求再次 Enter 才显示；Enter 打开对应扇区的字节检查。

## 6. 制盘流程

从设备列表选中目标 USB 后按 `p` 打开制盘方案 Modal。设备选择属于进入制盘前的工作区上下文，制盘内部不再提供第二个“选择设备”页面；没有固定目标时不能直接进入 Provision 工作区。

用户可见阶段固定为：

```text
1 制盘配置
2 分区预览
3 计划确认
4 执行
5 完成
```

内部 `ProvisionStage` 还包含只读计划生成、镜像导出、确认和结果等细分状态，但这些内部状态不改变上面的用户步骤语义。

表单 Normal 模式用 `i` 编辑当前字段；`h/l` 对多值字段分别选择上一个/下一个值，`Space` 保留循环或布尔切换语义。输入状态中的所有普通可打印字符都由输入控件消费，不能泄漏为全局快捷键；例如 `q` 是字符而不是退出。方向键移动光标，Enter/Esc 结束字段编辑。配置完成后 Enter 生成只读计划。

窄屏参数表单使用单列；密码行明确标注交换区或保密区及验证状态。“透传”“不涉及”等状态以可读文字显示，实际密码始终遮罩，长遮罩限制在当前字段宽度内。

普通文件系统区域的格式化交互由预检结论驱动：可安全保留时显示只读来源卷标，用户可按 Space 主动改为重新格式化；必须重建时格式化自动开启并显示“必须”，不能取消，用户只编辑目标文件系统和格式化后卷标。普通盘制作 mode0 的典型三分区重建因此不要求用户额外勾选三次格式化。

真实写盘必须再次经过精确 `YES` 确认和应用层安全事务。

制盘中的只读计划生成和镜像导出执行属于后台等待状态，不形成独立页面：`Planning` 在制盘配置页上显示状态模态框，`Exporting` 在计划确认页上显示状态模态框。等待模态框统一以整个终端 `frame.area()` 为坐标系居中，不能依附当前局部 Pane。后台状态仍保留用于单飞、输入阻断和任务生命周期管理，但不会替换用户原来的业务上下文。

## 7. 长操作进度

备份创建、恢复和制盘共用 `OperationRunState`，不维护三个互不兼容的运行页。

进度被明确拆成三个维度：

- `OverallProgress`：整个操作的总体进度，使用 0～10000 基点；
- `StageProgress`：逻辑步骤序号，例如 `2/7`；
- `WorkProgress`：当前步骤内部的 sector/byte 工作量，例如 `11807 / 15661 sector · 75%`。

正常尺寸运行页固定为四层：

- “总体进度”：只显示整个任务的一行总体 Gauge 与百分比，不重复当前步骤；
- “当前任务”：显示 `N/M · 阶段名`、目标、醒目的当前步骤、动态描述、最近活动时间，以及当前 `WorkProgress`；
- “运行记录”：只保留步骤开始/完成、警告、失败、回滚和重要检查点，不为每一个 sector 生成历史行；
- “安全提示”：页面底部只占一行。

Running 阶段没有真实 Notice 时，全局消息栏收起，不再重复“安全写盘事务执行中”等等价状态，也不显示额外“就绪”空行。总体百分比由应用层事件生产者提供，渲染器不能自行猜测业务百分比。

`ProgressSpan` 用于把事务内部进度映射到总体进度区间。高频快照在运输层合并，警告、错误、回滚和阶段边界不会被丢弃。

正常终端刷新最短间隔为 50 ms，即上限约 20 Hz。存储层仍可产生更高频的扇区事件，但不会要求终端同频刷新。

共享页面由 `operation_progress_render.rs` 组织，“当前任务”卡片由 `operation_progress_status.rs` 独立负责，以保持布局职责边界。

### 7.1 统一结果汇报页

运行页负责展示“正在发生什么”，结果页只展示“最终得到了什么”。结果展示分为两类：

- 备份创建这类轻量结果可以继续使用 `ui/operation_result.rs`；
- 制盘和元数据恢复包含可交互的分区/全盘结构，统一使用 `ResultWorkbenchState` + `result_workbench.rs`，固定为“分区结果 / 全盘布局 / 验收与执行”三个顶层 Pane。

单备份删除、批量删除和 keep-N 清理属于通知型操作：输入、规划和执行状态都作为备份列表上的模态覆盖层展示，计划完成后直接进入确认 Modal，执行结束立即回到备份列表并通过 Notice 汇报成功或失败，不再创建独立等待页、Review 页或 Result 页。

Result Workbench 的交互合同：

- Pane 焦点和表格行/列激活是三种独立状态；
- 当前表格行只使用统一 selected-row 底色，整行不得加粗，也不得自行使用 accent/蓝色反白；
- 当前激活列的单元格才提亮并加粗，字段原有成功/警告/危险等语义色必须保留；
- “全盘布局”是一个完整顶层 Pane，容量地图与区域列表位于同一窗口内，区域列表不能再形成第二个焦点窗口；
- 在全盘布局内用 `j/k` 移动区域选择，容量地图同步激活对应几何，并在激活区域下方显示与设备列表相同的 `▲` 标记；
- 分区与全盘区域只按 `start_lba + end_exclusive + DiskRegionKind` 的精确几何关联；Protocol、Free、LCE、Tail 等非分区区域不得“就近”映射到某个分区。
- “分区结果”是正式共享表格，完整支持 `j/k` 选行、`h/l` 切换激活列、`H/L` 横向滚动、`</>` 调整整列顺序、`0/$` 首末列、`s/S` 排序/清除排序、`y/Y` 复制单元格/整行；
- `Y` 的整行复制顺序必须跟随当前视觉列顺序，不能退回固定逻辑列顺序；
- `h/l` 到达首末列时只停在边界，不得隐式切换 Result Pane；Pane 切换只由 `Tab/Shift-Tab` 或 `Ctrl-w h/j/k/l/w/W` 负责。

结果页不得继续复制运行日志或“最近进度事件”。制盘成功页优先展示最终盘型与总容量、每个分区的角色/文件系统/几何/最终状态、完整全盘布局、协议/几何/格式化读回验收，以及制盘前自动备份与总耗时。

恢复成功页同样使用 Result Workbench。恢复后的 `DiskLayoutModel` 必须由 application 层基于真实恢复结果投影：EDP 盘使用已解析的 typed `PartitionRole`，Plain 盘使用恢复后的真实分区几何；TUI 不解析 `role: String` 来猜测布局。布局投影失败只作为结果警告，不得反向把已经读回验证成功的元数据恢复判成失败。

恢复后的格式化、原密码验证、加密格式化和密钥域重建继续使用各自既有安全事务与独立 `YES` 确认，但 UI 以恢复 Result Workbench 为背景叠加 Modal，不再跳到另一套结果页面。选择 Protocol/Free/LCE/Tail 等非分区区域时，可执行分区必须为空，禁止沿用上一次分区选择。

制盘写入前只把无敏感信息的 `ProvisionResultSnapshot` 留给结果页；完整 `PreparedProvision` 仍移交后台写入任务，不为了结果展示在 TUI 中额外保留密钥材料副本。恢复 Result Workbench 同样不得保存密码、FileKey 或其他密钥材料。

总体和当前工作进度条使用同一套高对比度粗体标签样式，工作进度文字不能因为使用次级进度色而降低可读性。

## 8. 视觉与表格

TUI 统一使用主题模块提供的 24-bit TrueColor 低饱和配色，并保留 ANSI256/ANSI16 降级。

禁止各工作区自行硬编码私有高饱和颜色。分区、盘型、风险和焦点使用统一语义色。

当前焦点至少通过边框、标题或表面变化之一明确区分；选中行、激活列和 Pane 焦点是不同状态，不能只靠同一种反白效果表达。

所有交互表格复用统一列模型、显示宽度计算、复制规则、排序、列移动和滚动条逻辑。

桌面大窗口的备份列表随高度增长，不设 16 行的固定上限。设备列表按当前记录数收缩；检查概览设有高度上限，把余量交给详细证据。分页和绘制使用同一套窗口尺寸。

容量图保留原有百分比刻度、刻度线、单组区域色块及选中标记，不增加容量比例轨道或说明行。空间允许时每个区域保留至少 3 格，防止小区域消失；选中标记对齐对应色块。精确容量、占比及 LBA 在区域表中显示。

备份表值、过滤索引、列宽和设备分组在数据/查询/筛选/排序变化时更新；选择和装饰动画不触发全量重建。缓存只用于展示。结果表格与复制数据复用同一状态投影，缺少执行结果时显示“未确认”。

默认空闲装饰重绘为 1 秒，Reduced 为 2 秒；后台运行保留原有动画频率。Off 模式运行中的耗时与等待文本每秒更新，空闲时不进行装饰重绘。

macOS/Linux 桌面回放使用 `uv run --locked python scripts/tui-replay.py --binary ~/.local/bin/edpcli --scene provision-result-partial --size 200x60`。每次在 `~/.local/state/edpcli/tui-replay/` 新建 run-id 目录，记录二进制版本/SHA、行列、输入、PID、退出码及 ANSI。`--steps` 接受 JSON 数组（keys/wait/resize），`--timeout` 限制总回放时间；超时或异常只清理该次创建的进程组。

真实只读回放显式使用 `--live-read-only`（需要管理员身份时加 `--sudo`），只接受设备/备份导航和只读检查按键；恢复、格式化、删除、制盘等写入测试仍使用独立 HIL 流程。演示新增 `provision-result-partial` 和 `provision-result-rollback-failure`，结果来自应用层真实类型的内存夹具，不进行设备操作。

## 9. 安全边界

TUI 是应用服务的前端，不直接拥有裸盘安全策略。

必须保持：

- 外部介质文本渲染前过滤终端控制字符；
- 后台 worker 不直接写 stdout/stderr；
- 同类后台任务使用单飞和代次保护；
- 真实写盘复用 CLI 相同的 `TargetSession` 和事务服务；
- 关键阶段内 `q`、`Esc`、`Ctrl-C` 只登记延迟退出；
- Modal 通过共享覆盖层绘制，不得清空其下方工作区；
- 全局底部状态/安全提示保持固定布局，不因局部页面进度变化发生跳动。

任何 TUI 改动如果改变真实写盘授权或事务语义，必须在应用层先完成对应设计和测试，不能只通过前端快捷键实现。
