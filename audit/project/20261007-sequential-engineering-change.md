# 顺序工程化变更核查

日期：2026-10-07。本轮先阅读现行架构、Python 工具链、制盘规范和工程架构审计，再按用户指定顺序修改。当前行为以 `docs/` 的标准文档为准；本文是变更与验证证据。

1. 工程环境：保留已有 Python >=3.11 / uv 锁定合同，补充 fast/full watchdog、全仓审计和构建事实入口的早期版本预检。系统 Python 3.9 实测返回明确提示。CI repository contract 对每次 push/PR 执行全仓审计并始终上传报告，候选仍不自动导致失败。
2. API：将 application 的共享支持、文件系统、元信息、身份、覆盖、布局、分区表门面改为显式导出。格式规划测试改用 typed 入口；向导测试显式传入身份 pin；设备扫描测试直接覆盖 catalog scanner；恢复后格式化测试与生产入口共用返回评估的注入式服务。删除四个旧便捷包装和已被观察门禁吸收的独立系统盘包装，登记退役符号并增加回流回归。备份证明构造与来源绑定提交能力继续保留。
3. 业务评估：将密码意图、必需格式化、区域处置 preflight 和结果投影移至 application。TUI 保留编辑、验证代次、焦点与状态适配；提交仍独立复核设备、来源和备份。已有状态/密码/保留/重建回归继续覆盖行为。
4. 能力边界：提供 CommandExecutor、DeviceObserver 和 WriteLeaseProvider/WriteLease；TargetSession 独立消费观察与租约，可使用内存适配。宿主租约拒绝同进程同盘并发写会话，并按平台 guard → 租约的顺序释放；所有原有几何、重开、身份校验、事务和回滚状态保持。共享模拟磁盘编号的集成测试通过测试支持锁隔离夹具，生产租约仍立即拒绝同盘并发。旧 CmdRunner 仍用于未迁移的宿主只读探测；没有宣称全仓设备接口迁移完成或新增跨进程锁保证。
5. 资源：格式化驱动在卷大小分配前检查元数据写集；官方格式计划与 Plain 写计划执行累计预检。默认累计镜像有效载荷 64 MiB、按八份写集计费的工作有效载荷 512 MiB；Plain 还计入协议前缀和旧 LCE 清理写集。预算不等于分配器/RSS 硬上限。未引入流式写计划或拆 crate。

本轮没有新增冗余类别，沿用全部 13 条规则。完整[候选处置清单](20261007-sequential-engineering-disposition.tsv) 按 `rule + path + subject` 记录每个匹配及重新核查条件；未变化的规则、符号和检测证据复核先前保留依据，新增 typed 规划与端口注入能力、变化的计量消费者另行核对。不能把候选数量变化当作行为正确性证明。

- `uv run --locked python scripts/test-full.py --profile full --deadline-seconds 900`：观察同一运行会话至退出 0；8 套件 / 10 工件及 doctest 通过，0 失败，42.29 秒。
- Windows GNU x86_64 全目标 Clippy（拒绝警告）通过；Linux GNU x86_64 全目标编译检查通过。它们是交叉编译检查，没有在这两个平台执行测试二进制。
- 全仓冗余审计：747 个文件、13 条规则、确认问题 0、候选 175；处置清单的唯一键、检测证据及完整覆盖均通过核验。
