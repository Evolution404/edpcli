# edpcli 终端界面重构方案与实现交接

日期：2026-09-27

状态：**待实现的产品设计规格**。本文件不表示这些行为已经实现。

审计基线：原始 UI 截图/结构审计基于源码 `998adfec91ed`（v2.4.0）；2026-09-27 K6 补充审计已对齐 `main 06e16dacfbf8`（v2.5.0）。实现必须以执行时最新 `main` 为代码事实源，两份 audit 规范定义目标行为。

范围：整个 TUI 的信息架构、所有现有功能入口、导航、表单、反馈、终端适配与安全交互。CLI 命令与协议语义保持兼容。

配套专项规范：`audit/ui/K6_TUI_PRODUCTIZATION_SPEC.md`。该文件定义 K6 文件级无损迁移在制盘 P2～P7 中的来源密码、迁移统计、规划进度和实盘验收；K6 相关细节以后者为准，但必须实现为本文件同一套 P0～P8 制盘流程。

## 1. 结论与设计决策

采用 **4 个一级 Tab：设备 → 制盘 → 备份 → 检查**，按此顺序循环。默认打开设备页。

| 一级 Tab | 用户要完成的事 | 首屏职责 | 下钻内容 |
|---|---|---|---|
| 设备 | 找到盘，确认是谁的、是否可操作 | 设备列表与简短摘要 | 设备详情、关联备份；进入制盘、备份、检查 |
| 制盘 | 把指定盘制作成目标模式 | 选择目标或继续当前草稿 | 保存现状、选择模式、参数、计划、确认、执行、结果；镜像导出分支 |
| 备份 | 找到备份，了解能恢复什么，管理备份 | 备份列表、搜索与筛选 | 备份详情、覆盖范围、创建、校验、恢复、删除、保留策略清理 |
| 检查 | 只读理解设备或备份的结构与原始数据 | 选择检查对象或继续当前检查 | 概览、结构与字段、磁盘布局、扇区查看器 |

核心决定：

1. **Tab / Shift-Tab 只切换一级 Tab**。普通浏览、制盘选盘、模式选择、参数、计划、检查子页均遵守。内部面板使用 `Ctrl-w w/W`，二级视图使用 `1…4`。
2. **列表 Enter 不再触发制盘**。D0 设备列表 Enter 固定激活“当前设备”Pane；`p` 专门进入制盘，`i` 专门进入检查。设备页不再按终端宽度改变 Enter 语义。
3. **快捷键仅集中在底部一条上下文操作栏**。删除正文“可用操作”和标题内的重复按键清单。完整操作从 `m 更多` 和 `? 帮助` 获取。
4. **列表用于找对象，详情用于读信息，流程页用于执行操作**。默认列表不承载完整硬件标识、摘要、Manifest 和全部诊断证据。
5. **备份的文件校验、覆盖范围、目标匹配分别表达**。禁止用一个“健康”标记概括三件事。
6. 一级 Tab 切换保留当前位置和未执行草稿；明确替换目标、丢弃草稿和执行危险操作时才要求确认。
7. 保留现有 application 服务、安全检查和事务语义；界面重构不能绕过它们。

不增加“首页”“统计”“设置”一级 Tab。帮助、命令、任务进度均为全局辅助页面。当前会话任务面板是小范围新增展示能力，不包含跨启动历史数据库或后台调度器。

## 3. 统一页面骨架

从上到下固定为：

1. **应用栏（1 行）**：`edpcli v2.5.x`；右侧真实权限状态、活动任务摘要。空闲时不播放 CORE 状态动画。
2. **一级 Tab（1 行）**：`设备  制盘  备份  检查`；仅当前项高亮。
3. **页面上下文（1 行，按需）**：标题/面包屑、当前对象。二级页面必须有，例如 `备份 > 2026-09-27 10:24 · 王伟 > 覆盖范围`。
4. **主内容区**：列表、详情或当前流程步骤。二级视图栏占用内容区，不与一级 Tab 混用。
5. **状态反馈（最多 1 行，按需）**：最近操作结果、加载错误等。长错误进入详情；同一个警告不在多处重复。
6. **上下文操作栏（1 行）**：当前可用操作和必要导航。宽度不足时按优先级缩减，完整命令进更多菜单。

### 3.1 操作栏规则

- 宽屏设备页示例：`Enter 详情 · p 制盘 · b 备份 · i 检查 · / 搜索 · m 更多 · Tab 切页 · ? 帮助`。
- 宽屏备份页示例：`Enter 详情 · Space 勾选 · R 恢复 · v 校验 · m 更多 · Tab 切页 · ? 帮助`。
- 小屏优先保留 `Enter`、当前主要动作、`m`、`Tab`、`?`；二级页必须保留 `Esc 返回`，危险确认页必须保留 `Esc 取消`。
- `r`、`q` 等低频操作可移入更多菜单/帮助，但仍可使用。隐藏提示不改变实际键位。
- 同一动作若有兼容别名，合并为一个提示；不出现两段同义操作。优先删除无价值的别名。
- 正文中的“预览计划”“开始备份”等是可聚焦控件，不能再附带整排快捷键。
- 更多菜单列出当前页全部业务动作；每项带可用性与禁用原因。危险操作置于末组，不能默认选中。
- 帮助内分“全局”“当前页面”“高级键位”，和动作实现共享数据源。

### 3.2 文案与视觉

- 用户界面统一中文：`检查`、`普通盘`、`元数据备份`、`深度备份`。技术详情保留 `Inspect`、`Plain`、`Metadata/Deep`、原始字段名作为术语。
- 一个页面一个主标题；最多一层主边框，内部以分组标题和留白区分。避免每条统计单独画框。
- 选中项用背景、左侧标记共同表示；焦点用边框/标题标记。多选勾选与光标选中必须可区分。
- 成功绿、注意黄、错误红、中性灰、当前操作强调色；颜色须伴随文字，不能仅靠颜色辨别状态。
- 不把所有型号、标识和数值上色。默认文字色，只有真正需要判断的信息使用强调色。
- 容量统一以 GiB/MiB 显示，技术详情给出精确 bytes/sectors；明确区分“源盘容量”和“备份文件大小”。
- 不推断时间戳的时区。能确定的时间转换为本地并注明约定；无法确定来源时区的历史值保持原值并标明未知。
- 只对展示文字做截断；详情能查看/复制完整值。标识和长路径使用中间省略，姓名/部门使用尾部省略。
- 外部文本继续执行终端控制字符过滤；布局按显示列宽计算，覆盖中文、组合字符与窄屏。

## 4. 页面树与路由契约

```text
设备 D0
  └─ 设备详情 D1：1 概览 / 2 分区 / 3 身份证据
       ├─ 关联备份 → B0（携带显式筛选条件）
       ├─ 制盘 → P0/P1（传入目标候选）
       ├─ 创建备份 → B2（传入源盘候选）
       └─ 检查 → I1（固定检查源）

制盘 P0 目标选择 / 继续草稿
  └─ P1 保存现状
       └─ P2 选择模式
            └─ P3 参数配置
                 └─ P4 计划预览
                      ├─ P5 写盘确认 → P6 执行 → P7 结果
                      └─ P8 导出路径 → P6 导出进度 → P7 导出结果

备份 B0
  ├─ B1 备份详情：1 概览 / 2 覆盖范围 / 3 文件与证据
  │    ├─ 检查 → I1
  │    ├─ B3 校验 → G2 任务结果
  │    └─ B4 恢复：选目标 → 对比与预览 → 确认 → 执行 → 结果
  ├─ B2 创建备份：选源盘 → 选类型 → 确认 → 执行 → 结果
  ├─ B5 删除：对象清单 → 确认 → 执行 → 结果
  └─ B6 保留策略清理：输入策略 → 计划 → 确认 → 执行 → 结果

检查 I0 选择对象 / 继续检查
  └─ I1 检查对象：1 概览 / 2 结构与字段 / 3 磁盘布局 / 4 扇区
       └─ I2 字段详情、I3 跳转、I4 搜索（局部详情或弹层）

全局：G0 帮助、G1 命令/更多菜单、G2 当前会话任务、G3 错误详情
```

路由规则：

- 一级切换不压入“返回”栈；每个 Tab 保存自己的子路由、滚动、焦点、筛选和草稿。
- 显式跨页动作（例如从备份详情进入检查）携带返回位置；检查根页 Esc 回到该详情和原选中对象。
- 从一级 Tab 直接进入检查，则检查根页 Esc 回对象选择，不跳到偶然选中的设备。
- 列表高亮行不等于操作目标。设备源使用经过身份固定的引用，备份使用路径与摘要；不要依赖共享 selected 下标。
- 刷新保留稳定对象；原对象消失时展示“对象已移除”，清空危险动作的资格，不能自动改成相邻盘。
- 根页 Esc 不退出应用；筛选取消、子页返回与退出分别处理。

## 5. 设备 Tab

### D0 设备列表

**目标：保留三窗口布局，但明确职责，避免信息重复。**

D0 固定由三个 Pane 组成：

1. **设备列表**：比较和选择设备。
2. **当前设备**：查看当前选中设备的可交互分组详情。
3. **设备状态**：查看整个扫描环境的总体状态。

宽屏和标准宽度同时展示三个 Pane；Compact 宽度只展示当前聚焦 Pane。`Ctrl-w w/W` 在三个 Pane 间循环，`Ctrl-w h/j/k/l` 保留空间切换。切换 Pane 不得改变当前设备。

#### 设备列表 Pane

正式列顺序固定为：

`设备 → 容量 → 部门 → 姓名 → 盘型 → 状态 → 备份 → 型号`

状态列只显示简短行动状态，如“可用 / 需权限 / 读取异常 / 非 USB”；完整错误原因下沉到当前设备 Pane。备份列只显示已确认备份数量，不能把“可能相关”混入确定数量。设备表和全项目其它表格统一遵循第 9.2 节的列焦点/视口/排序协议；列定义和业务默认顺序不得变化。

#### 当前设备 Pane

该 Pane 是可交互分组视图，不是静态卡片。固定五组：`身份信息 / 容量布局 / 状态与诊断 / 备份关系 / 协议摘要`。默认展开“身份信息”和“容量布局”，其余默认折叠。

- `j/k`：移动当前分组选择。
- `o`：展开/折叠当前分组。
- `Ctrl-w w/W`：切换到其它 Pane。
- `Esc`：退回设备列表 Pane，不改变当前设备。

身份信息展示身份依据、onlyid、device_id、硬件序列号、VID:PID；“身份依据”只说明当前有哪些唯一识别证据可用，不再把当前快照与自身比较后显示“物理介质一致”。姓名/部门已经在列表中，不在首屏机械重复。

容量布局必须使用真实读取到的分区/LBA 信息绘制**比例进度条**，并统一经过 `InspectTopology → DiskLayoutModel` 真相源；进度条使用当前 Pane 的可用宽度，不设置固定 52 字符上限。D0 的容量数值统一使用十进制 GB/MB，与设备列表及系统磁盘容量口径一致。EDP 盘显示启动区/交换区/保密区/二合一区/兼容区等协议分区；Plain 普通盘必须解析实际 MBR/GPT，支持主分区、EBR 逻辑分区、GPT 分区项和严格验证后的 FAT/exFAT/NTFS 文件系统。分区表已经完整读取时，分区之间的 gap 明确显示为“未分配空间”；只有缺乏可靠分区表证据时才显示未知，绝不能把未知推断为空闲。普通盘分区表读取失败时直接显示具体失败原因。

状态与诊断展示当前行动状态、总线、拒绝/读取异常原因。备份关系区分已确认与可能相关。协议摘要只展示与当前盘型实际适用的信息：EDP 盘显示正式模式和协议分区记录；Plain 显示物理分区表类型与分区记录，不得展示或暗示 EDP 专属状态。

#### 设备状态 Pane

只展示整个扫描环境：总设备、可用、需处理、EDP、普通盘、需权限、读取异常、扫描状态。不得展示某一块盘的身份字段，也不再把备份总数混入总体状态。

#### D0 操作契约

- Enter：激活当前设备 Pane；所有宽度语义一致。
- `p`：制盘。
- `b`：创建备份。
- `i`：检查。
- `/`：搜索。
- `r`：刷新。
- `o`：仅在当前设备 Pane 中展开/折叠分组。
- `Ctrl-w w/W`：三 Pane 循环。

空状态必须区分“没有设备”“正在扫描”“筛选无结果”；扫描失败不得伪装为没有设备。

### D1 设备详情

固定对象标题：设备路径、型号、源盘容量；不跟随背景列表移动而改变。

| 二级视图 | 展示内容 | 操作 |
|---|---|---|
| 1 概览 | 姓名、部门、盘型、可操作状态、已确认/可能相关备份数量、最近备份时间 | 制盘、备份、检查、查看关联备份 |
| 2 分区 | 简洁布局条；分区角色、文件系统（已知时）、容量、起止范围 | 在检查页查看对应分区 |
| 3 身份证据 | onlyid、device_id、VID:PID、USB serial 可用证据、容量/扇区大小、识别结论和依据 | 复制完整字段、进入技术检查 |

尚未读取的分区信息显示“未读取”，提供只读加载；加载失败不能伪造为普通盘或空盘。敏感原始序列号若现有数据只提供摘要，就继续展示摘要。

空状态：无设备时显示“未发现可用设备”和刷新动作；权限不足和扫描失败必须区别于无设备；有旧数据时加载失败保留旧列表并标“更新失败”。

## 6. 备份 Tab

### B0 备份列表

**目标：按时间、人员、盘型找到正确备份。**

默认时间倒序。列表第一业务列为时间，移除作为默认主列的长文件名。筛选与排序是本次新增的界面能力，底层数据不足时补充只读投影。

| 区域 | 具体内容 |
|---|---|
| 顶部工具行 | 当前显示数/总数、已选数、搜索词、筛选条件、排序方式 |
| 默认列表列 | 选、序号、时间、容量、部门、姓名、型号、盘型、健康、VID:PID、onlyid、名称 |
| 默认列序原则 | 上述顺序是备份表启动时的业务默认顺序；运行时仍可用 </> 移动整列，S 只恢复行排序，不重置列顺序 |
| 选中摘要（最多 6 行） | 姓名/部门、来源设备、创建时间、备份类型、覆盖范围一句话、文件校验结果 |

搜索覆盖人员、部门、型号、onlyid、文件名；默认不对未加载的二进制内容进行全文扫描。筛选菜单提供全部/当前显式设备关系、元数据/深度/未知、校验状态；关系筛选显示比较目标及“已确认/可能相关”的区分。排序菜单提供时间新旧、姓名、源盘容量。

列表首页不展示“硬件冲突”。只有用户主动选择“比较设备”或处于恢复流程时，才展示匹配关系。

勾选规则：

- Space 切换当前记录；勾选状态绑定备份引用，排序和刷新不应把勾选转移到别的对象。
- 过滤后隐藏的勾选不丢失，工具行显示“已选 3（其中 1 条不在当前结果）”。
- 删除入口明确显示“删除当前记录”或“删除已选 3 条”；清单包含全部将删除对象，不能只列当前可见行。
- 本版多选仅用于删除。恢复、检查、校验作用于当前行，不把选中集合隐式变成批量写盘。
- 更多菜单提供新建备份、清除勾选、筛选/排序、保留策略清理、刷新；危险动作放末尾。

### B1 备份详情

| 二级视图 | 内容 | 禁止事项 |
|---|---|---|
| 1 概览 | 备份时间、姓名/部门、盘型、来源型号/容量、备份类型、文件校验、覆盖范围总结 | 不默认与隐藏设备比较；不展示一屏原始标识 |
| 2 覆盖范围 | 区域、采集状态、已采集/已知总扇区数、原始证据/派生结果标记；区域可展开细节 | 不用覆盖率暗示可恢复全部文件 |
| 3 文件与证据 | 完整路径、实际文件大小、容器格式、SHA-256、原始来源标识、Region/Extent/Artifact 明细入口 | 不把扫描编号当永久 ID；不截断到无法查看 |

三种状态的固定语义：

| 维度 | 示例 | 数据依据 |
|---|---|---|
| 文件校验 | 未校验 / 校验中 / 通过 / 失败 / 无法读取 | 实际校验结果；扫描已校验可直接显示通过，不能伪造校验时间 |
| 覆盖范围 | 协议区完整；分区元数据部分；普通文件数据未完整采集 | Manifest 与实际 artifact；不知道总量时显示未知，不画满进度条 |
| 与目标的关系 | 与 disk4：同一物理介质 / 协议相关 / 无法确认 / 不同介质 | 当前明确目标 + application 身份关系判定 |

“区域采集完整”仅表示该区域定义的范围完整，不等价于“全盘备份完整”。默认覆盖视图用简短中文名称，如“分区 1（type1）”“盘尾证据”；原始 role/id 在展开行中保留。缺少可信映射时显示原始名称，不能猜测分区用途。

去掉首页多组十格字符进度条，覆盖详情以表格表达。例如 `分区 1 | 部分采集 | 72 / 20417 扇区`，能比进度条更清楚地表达极小覆盖量。未知总量显示 `72 / 未知`。

每个页面仅保留一处能力说明：**“此备份不保证包含普通分区的全部文件数据。”** 深度备份明确为额外文件系统/目录元数据与证据，不称为完整镜像，不称为原子文件系统快照。

### B2 创建备份

1. 选择源盘：从设备页进入时预选该盘，显示完整摘要；从备份页进入时直接提供设备选择器。
2. 选择类型：元数据（协议、选定分区元数据、盘尾证据）；深度（额外文件系统/目录证据，耗时更长，仍不读取普通文件负载）。
3. 确认摘要：源盘、类型、当前有效输出目录、覆盖能力、预计耗时若未知则标未知。
4. 执行：当前阶段、已耗时、已处理量（若后端有）、最近一条状态；详细日志折叠。
5. 结果：实际产出路径、文件校验、采集成功/部分失败信息，入口“查看备份”“继续原流程”。

本轮保留现有精确 YES 确认契约，只把说明改为“读取源盘并在本机保存备份”，不称为物理写盘。是否简化只读备份确认属于后续独立决策。输出目录本轮展示现有配置，除非后端已有支持，不顺带新增配置系统。

制盘前备份使用同一流程组件；结果应返回原制盘草稿，不要求用户重新选盘。失败时提供“重试”“返回”，只有用户明确选择“跳过备份继续”才能继续制盘。

### B3 校验

固定当前备份引用后后台校验；列表显示进行中，允许切 Tab。成功更新该记录状态；失败展示具体原因并禁止该文件进入恢复计划。文件在任务期间变化，旧结果不得附着到新内容。

### B4 恢复向导

1. 备份已固定，选择目标 USB；不依赖设备页当前高亮。
2. 对比页左右列出“备份来源 / 目标设备”：型号、源容量/目标容量、身份结论与证据；下方显示实际拟写范围和限制。
3. 预检查给出可执行或阻止原因，完全遵循现有 application 规则。UI 不能把“可能相关”升级为“同盘”，不能提供绕过身份检查按钮。
4. 确认页固定显示备份、目标和覆盖风险，精确 YES 后执行。
5. 结果区分成功、拒绝执行、失败且回滚成功、回滚未完成、状态未知；文案跟随真实结果能力，不臆造“已恢复原状”。

匹配状态不是恢复许可；最终许可必须来自同一份经过校验的计划与后端安全链。

### B5 删除 / B6 保留策略清理

- 删除：列出固定对象、时间、归属、路径、将释放大小（可获得时）；不可删项显示原因；按原有确认要求执行。
- 清理：输入每组保留最近 N 份；生成预览，分组列出保留、删除、保护对象和原因；没有可删除对象时直接给结果，不弹空确认。
- 两者复用“预览→确认→执行→结果”框架；继续按路径+SHA-256 复核、保护原盘备份和每盘至少一份的底线。
- 多对象部分成功时给出成功/跳过/失败数量和逐项结果，不显示总的“全部成功”。

## 7. 制盘 Tab

**目标：每一步只解决一个问题，始终知道将修改哪块盘。**

流程上方用一行步骤条：`目标 → 保存现状 → 模式 → 参数 → 计划 → 执行`。确认属于计划到执行的门槛；结果归入执行结尾。导出是计划页的独立分支。

所有步骤显示紧凑目标条：设备路径、型号、容量、身份固定状态。完整证据下沉到目标详情；不常驻展示内部事务术语长清单。

| 页面 | 展示什么 | 功能和退出规则 |
|---|---|---|
| P0 目标 | 可用 USB 列表、不可用原因；已有草稿时显示“继续 disk4 草稿 / 重新选择” | 选盘进入流程；更换目标将影响草稿时明确确认；Tab 自由切页 |
| P1 保存现状 | 该盘已有备份数量/最近时间、当前保存选择 | “先创建元数据备份”默认项；可进入深度备份；可明确跳过；现有备份不代表当前状态已保存 |
| P2 模式 | mode0/1/2/3/普通盘的正式名称、一句话用途、目标分区示意、当前盘型；说明数据处理将自动判定保留/迁移/重新封装/重建/删除 | 选择后进入参数；模式名称与语义使用现有 ProvisionTarget，不重新发明盘型；K6 不是额外模式 |
| P3 参数 | 分组字段、来源数据与来源密码域、当前字段说明、校验信息和紧凑布局预览 | 字段 Enter/i 编辑；明确的“预览计划”控件；支持草稿保留；EDP→Plain 也必须可输入/验证来源密码 |
| P4 计划 | 当前→目标变化、类型化数据处置、K6 迁移统计、保留/写入/格式化区域、目标容量、警告、计划有效状态 | 返回修改、导出镜像、进入写盘确认；改参数后必须使旧计划失效；只有真实 `Migrate` 才显示 K6 |
| P5 确认 | 目标设备、目标模式、真正会改变的内容、备份状态、精确 YES 输入框 | Enter 仅在精确满足条件时提交；Esc 取消；不显示装饰性成功标志 |
| P6 执行 | 真实阶段、K6 数据写入阶段、已耗时、可用进度、最近状态；详细日志可展开 | 关键写入阶段导航受保护；退出只能按后端安全检查点处理；进度来自类型化事件 |
| P7 结果 | 明确结果、实际盘型/校验、K6 实际迁移与读回结果、备份或产物路径、部分失败项 | 返回设备、查看结果/日志；不自动重试写入 |
| P8 导出 | 输出路径、绑定目标、预计/实际产物信息 | 导出进度与结果；明确镜像仍绑定目标，不能表达为任意盘可用镜像 |

### P3 参数信息分组

统一顺序：

1. 来源摘要：当前盘型、可读取区域、已知文件系统；未知显示“待规划阶段解析”。
2. 来源数据与密码域：按源盘真实 Share/Encrypt 域显示来源密码与验证状态；来源字段由源盘和本次读取需求驱动，不再只按目标 mode 决定。
3. 身份：官方目标显示标签 ID、姓名、部门、适用的安全标签；Plain 目标不显示无意义的官方身份输入。
4. 目标分区：角色、容量、起点、保留状态；精确单位和允许范围贴近字段；剩余容量/超出容量单独一行。
5. 目标密码域：仅官方目标显示，按交换域/保密域与来源密码明确区分。
6. 格式化：每分区是否格式化、文件系统、卷标；未选择格式化时不显示可编辑的无效子选项。
7. 密码策略：强制修改、复杂性策略、错误次数等现有选项；不默认挤占首屏。

普通盘目标仍支持 1～4 个主分区，每分区起点、容量、文件系统、卷标，明确添加/删除分区控件并保留可配置 gap；**但如果源盘是 EDP，普通盘 P3 仍必须显示真实来源数据与来源密码域，并执行来源密码探测/验证。** Plain 没有目标密码域，不代表可以隐藏迁移所需的旧密码。删除这里的分区草稿只修改计划，不能与删除备份共用含混文案。

K6 专项的来源密码显示规则、Plain→EDP / EDP→Plain / EDP→EDP 差异见 `K6_TUI_PRODUCTIZATION_SPEC.md` 第 7～8 节。

字段行为：

- 上下移动字段；Enter 编辑/提交当前值；Esc 撤销此次未提交编辑，恢复进入字段前的值。
- Space 只切换当前选项；容量比例分配作为命名控件展示，不能在任意字段按 Space 意外改变全局模式。
- “填满可用容量”“验证来源密码”是当前字段的动作，通过更多菜单可发现；仅对适用字段启用。
- 当前模式无关字段不显示。必填错误在字段旁和分组摘要中显示一次，生成计划时定位首个错误。
- 保留现有默认值、密码继承、保留重制与容量独立编辑规则；本轮只整理展示和操作入口。
- 密码默认遮罩，不写入日志、复制摘要或任务历史。错误文案不得回显密码。
- 当前仅浏览参数时不显示“忙碌”。只有后台探测、验证、计划和导出任务才显示运行状态。

### P4 计划预览的优先顺序

1. 要操作的盘与准备结果。
2. 当前模式到目标模式，变化摘要。
3. 数据处理表：直接消费 typed disposition，展示保留、重新封装、K6 迁移、重建、删除。
4. 若存在 `Migrate`，显示 `K6 文件级无损迁移` 摘要和真实 manifest 文件数/字节数、源/目标角色、文件系统与来源密码状态。
5. 分区对照表：保留、重建、格式化、起点与容量变化；“重建目标文件系统 + K6 迁移”必须组合表达，不能只写“重建”。
6. 与本次执行有关的阻止项/警告。
7. “返回修改”“导出镜像”“确认写入”控件。
8. 技术详情：LBA 写入范围、LBA3 保留、MBR 提交、K6 transform/budget 等，可展开查看。

底层尚不能提供字段级变化时显示已有计划摘要，不推算或编造差异。K6 文件数/字节数只能来自真实 migration manifest；未知时明确显示未知。制盘成功但后续格式化失败必须显示部分成功，并解释最终状态；不能归并为单一绿色成功或笼统失败。K6 的完整计划表契约见 `K6_TUI_PRODUCTIZATION_SPEC.md` 第 9 节。

## 8. 检查 Tab

保留一级检查入口，因为它同时面向物理盘和离线备份，并承载专业分析。默认只读，与制盘的目标状态分离。

### I0 对象选择

提供“物理设备”“备份文件”两个来源选择控件，选择后列出现有扫描对象；能搜索已有备份。已有检查会话时提供“继续检查：对象摘要”和“更换对象”。首屏不再只写“请返回设备页按 i”。

从其他页的 i 进入时直接固定该对象。切换一级 Tab 不重新读取、不清空检查树；更换检查源才生成新的会话。

### I1 四个二级视图

| 二级视图 | 默认展示 | 功能 |
|---|---|---|
| 1 概览 | 来源、盘型/身份、容量、关键字段摘要、读取状态、需要关注的异常 | 查看字段、进入对应结构节点 |
| 2 结构与字段 | 左侧结构树，右侧当前节点字段与解释；窄屏逐层打开 | 展开/折叠、搜索、业务字段/原始字段切换、查看字段来源 |
| 3 磁盘布局 | 区域比例条、精确范围表、分区/协议/LCE/盘尾/未知区域 | 选区查看字段或跳到起始扇区 |
| 4 扇区 | 当前 LBA、字节偏移、Hex/ASCII、字段解释、原始/解码/混合状态 | 跳转、前后扇区、字节移动、复制选中字段/原始值 |

业务字段/原始字段作为第 2 视图中的显示模式，取代当前与面板焦点混在一起的四项栏。操作菜单暴露切换动作；`v` 在这个视图切换业务/原始，在扇区视图切换原始/解码/混合，页脚写清当前语义。

二级视图 `1…4` 仅在 Normal 模式生效。通过结构节点进入扇区视图时保存来源节点，Esc 回该节点，而不是退出整个检查。

### I2–I4 详情、跳转和搜索

- 字段详情：中文名、值、含义、来源 LBA/偏移、长度、证据状态；未知字段保留“未知”，不推断。
- 跳转：LBA 或绝对字节偏移，控件明确选择单位；显示合法边界。输入错误留在弹层并说明原因。
- 搜索：范围为结构与已缓存字段，显示范围限制、结果数和当前位置；不能声称扫描了整盘全部内容。
- 解码失败/未支持/锁定/未采集分别显示，不能显示空数据后让用户误认成全零扇区。
- 未知布局区域显示“未知区域”，不能当作空闲容量。屏幕范围沿用现有闭区间显示契约，内部计算不改。
- 深度备份已有的目录/文件系统派生结果在结构树节点内展示；`parsed/locked/unsupported/parse_failed/not_captured` 逐一保留。没有数据的数量显示“未知”，不显示 0。
- 不增加十六进制编辑、原始扇区写入或新的解密能力。

## 9. 键盘、焦点和模式契约

### 9.1 全局键位

| 键位 | 语义 | 限定 |
|---|---|---|
| Tab / Shift-Tab | 下一个/上一个一级 Tab，循环四项 | 确认弹层与关键写入有明确门禁，见下表 |
| Ctrl-w w / W | 下一个/上一个可交互面板或控件组 | 不切一级 Tab；不可见面板不能获得焦点 |
| Ctrl-w h/j/k/l | 面板方向切换 | 可保留高级别名；默认帮助不强迫新用户学习 |
| ↑/↓ 或 j/k | 当前列表/字段上下移动 | 文本模式字母必须成为输入 |
| ←/→ 或 h/l | 当前控件局部左右操作 | 表格中为激活上一列/下一列；树和输入控件保持自身语义；不得切一级 Tab |
| Enter | 打开当前对象 / 激活当前控件 / 提交当前字段 | 列表 Enter 恒为详情；不等价于 p |
| 1…4 | 当前详情页二级视图 | 仅 Normal，页面不足四项时其余无效 |
| Esc | 取消当前输入/弹层，或返回上一层 | 根页不退出，关键任务不强制中断 |
| / | 当前页搜索 | 仅页面支持搜索时启用 |
| m | 当前页面更多操作 | Normal；同时提供全部业务操作的键盘可发现入口 |
| ? | 上下文帮助 | Normal；输入模式按文字处理 |
| : | 命令面板 | Normal；只映射类型化动作，禁止 shell |
| q | 请求退出 | 仅 Normal；输入模式 q 是文本 |
| Ctrl-C | 请求退出/按安全策略延迟退出 | 不直接杀死关键 worker |

Normal 下常用业务键：设备 p 制盘、b 备份、i 检查；备份 b 创建、v 校验、R 恢复、d 删除、Space 勾选。更多菜单补齐全部能力。保留 gg/G、分页、n/N、gl、[/]、y/Y 等适用高级操作，和当前页上下文绑定。

### 9.2 全项目统一表格协议

所有可交互表格，包括设备、备份、制盘目标盘、制盘方案、Inspect 字段表，必须复用同一个 TableInteractionState 和自适应列布局；禁止任何页面维护第二套 h/l 横滚或私有排序状态。

| 键位 | 表格语义 |
|---|---|
| h/l | 激活上一列 / 下一列；新激活列仍在视口内时视口不动，越界时仅做最小必要跟随 |
| </> | 将当前激活整列与左/右相邻列交换位置；表头、数据、列宽和排序语义一起移动 |
| 0/$ | 激活第一列 / 最后一列，并将目标列带到对应视口边缘 |
| H/L | 整个表格视口向左 / 向右连续平移，每次 2 个 terminal cell，不改变激活列 |
| j/k | 上一行 / 下一行 |
| s | 按当前激活列排序；同列再次按下在正序/倒序之间切换 |
| S | 清除排序，恢复该表默认业务顺序 |

激活列必须在视口中可见，并优先获得完整内容宽度；为了展开激活列，可以压缩或暂时隐藏其它列。激活列不得使用省略号；若单个值本身宽于整个终端物理宽度，只允许按终端边界裁切，不能插入省略号。表头明确高亮当前激活列，并用 ↑/↓ 标识排序方向。

排序必须基于原始业务值而非截断后的显示文本。设备号、容量、备份数量等按数值排序；盘型和状态使用稳定业务枚举顺序；文本字段使用完整字符串。切换排序不得改变当前选中的业务对象：设备按稳定介质对象保持，备份按备份引用/路径保持，制盘目标按磁盘保持，制盘方案按 ProvisionKind 保持，Inspect 字段按字段身份保持。搜索/过滤、刷新和排序叠加时也不能把选择漂移到相邻对象。

所有表格标题和页脚使用同一套可发现提示：j/k 行 · h/l 激活 · </> 移列 · 0/$ 首尾列 · H/L 视口 · s 排序 · S 默认排序。树、表单、Hex 等非表格控件继续保留各自 h/l 语义，不受本节覆盖。

### 9.3 不同状态如何响应 Tab 和退出

| 状态 | Tab | Esc | q / Ctrl-C |
|---|---|---|---|
| 普通浏览、列表、制盘模式选择 | 切一级 Tab | 返回上一层/根页无操作 | 退出；有草稿时给出丢弃提示 |
| 制盘参数草稿/计划预览 | 保留草稿/计划并切页 | 返回上一步；确实丢弃时确认 | 同上 |
| 字段编辑 | 验证当前编辑；成功则提交并切一级 Tab；失败留在字段并显示原因 | 撤销本次字段编辑，回 Normal | q 是字符；Ctrl-C 请求退出 |
| 搜索编辑 | 保留已输入筛选，结束编辑并切一级 Tab | 恢复进入编辑前的筛选 | q 是字符 |
| 命令、跳转、帮助、更多菜单弹层 | 不切主页面，明确显示“Esc 关闭后切页”；弹层内上下选择，Ctrl-w 切控件组 | 关闭弹层 | 文本弹层 q 为字符；纯菜单 q 按退出策略 |
| YES 等危险确认弹层 | 保持确认弹层；显示取消入口，不泄漏到背景页 | 取消回预览 | q 为文本，不能绕过取消逻辑 |
| 只读扫描/检查/校验/计划生成 | 可切一级 Tab，后台继续；原对象和 generation 固定 | 离开进度页不等于取消任务 | 按现有任务生命周期安全收尾 |
| 备份创建/导出等文件产物任务 | 可切页看状态；任务锁仍生效，互斥动作禁用 | 返回前页，任务保持 | 若当前后端要求安全结束，继续延迟退出，不强制丢弃产物 |
| 真实写盘或受保护删除关键阶段 | 留在任务页，明确显示“执行中，完成后可切页” | 不终止事务 | 登记一次延迟退出，达到安全点后处理 |
| 任务结果 | 可切一级 Tab | 返回来源页面 | 普通退出 |

这张表必须实现为状态契约；不能让各页面用 `match _ => {}` 静默吞掉全局导航。临时禁止的动作须可见地解释原因。

输入优先级：活动输入/弹层消费文本 → 关键操作门禁检查控制动作 → 全局导航/帮助 → 局部页面动作 → 明确未处理结果。全局动作也必须经过安全门禁，不能先改路由再补检查。

## 10. 全局辅助页面与异步反馈

### G0 帮助

全局键位、当前页动作、高级键位、术语说明；在任何页面可打开，关闭后恢复原焦点。滚动帮助不改变背景选择。

### G1 命令面板 / 更多菜单

命令面板保留现有 devices/backups/provision/inspect/restore/backup-create/backup-deep/verify/delete/batch-delete/prune/refresh/help/quit 等动作和别名；映射到新路由和向导。`:restore` 在缺少备份时进入选择步骤，不能取隐藏状态执行。新增 `:tasks` 打开 G2。

提供可选择的命令列表、简短描述、可用性；用户不需要记住 `:backup-prune` 才能找到清理功能。更多菜单是相同动作目录在当前页的过滤视图。

### G2 当前会话任务与结果

通过应用栏任务提示、更多菜单或 `:tasks` 进入，非一级 Tab。

- 当前任务：类型、对象、阶段、开始时间/耗时、进度来源、是否允许退出。
- 当前会话已结束任务：最近最多 50 条摘要，可打开结果与已有日志；退出程序后不承诺保留。
- 日志按任务已有有界缓冲保存；不得无限增长，不增加新的敏感数据采集。
- 百分比仅在后端提供分母时显示；否则显示真实阶段和已耗时，不用动画伪造进度。
- 任务结果必须由类型化结果驱动，区分成功、部分成功、失败、拒绝、取消/未执行。
- 切 Tab 后任务完成，在应用栏给一次简短结果提示；严重失败持续可访问，不能几秒后彻底丢失。
- 与现有 single-flight/写入互斥保持一致。任务面板不是新并发任务队列，也不允许同时对同一介质启动互斥操作。

### G3 错误详情

展示“发生了什么、影响哪个对象、当前是否有修改、下一步可做什么”，技术日志折叠。错误在内容区可查看，不仅是一条被终端宽度截断的页脚。

所有页面统一覆盖：初次加载、刷新中保留旧数据、空列表、搜索无结果、读取失败、对象消失、权限不足、任务进行中、结果部分成功、终端太小。

## 11. 响应式与布局预算

继续采用现有宽度分界：小于 80、80–119、120–159、160 及以上；增加高度预算判断。**尺寸只改变排版，不改变动作和路由。**

| 尺寸 | 布局原则 |
|---|---|
| ≥120 列且 ≥30 行 | 列表配简短摘要；详情可左右分栏；制盘字段+说明双栏；技术证据仍需主动进入 |
| 80–119 列且 ≥24 行 | 主要内容单栏，列表下方 3–5 行摘要；详情二级视图切换；不强塞三面板 |
| 60–79 列或 18–23 行 | 列表/详情逐页显示；减少默认列，可将姓名和盘型合并为一行摘要；底栏缩减 |
| 40–59 列或 10–17 行 | 单内容区，可滚动；对象标识、当前页、返回/更多/切页优先保留；不显示装饰图表 |
| <40 列或 <10 行 | 显示窗口过小提示及安全状态；仍处理退出请求；关键任务继续受保护 |

列表高度按记录数和可用高度计算，不固定占一半屏幕。长列表保留滚动位置，摘要设置上限；短列表自然收缩。窄屏优先隐藏低优先级列，不能要求每次横向滚动才能看到时间和姓名。

正文溢出必须可滚动；当前焦点始终可见；完整值可在详情查看。危险确认页放不下目标摘要和确认输入时，要求扩大窗口或分步展示全部摘要，不能直接裁掉对象信息仍开放执行。

测试基准：40×10、60×18、80×24、120×36、160×48、220×60，另测超宽矮屏 160×18。纯文字、ASCII 降级标记同样可理解。

| `task.rs` 与各 task 模块 | 任务离开页面后的结果关联、会话任务摘要；继续复用 operation/generation 与互斥策略；为 K6 planning 增加类型化阶段/计数事件 |
| `application` 只读投影 | 必要时补充备份类型、文件大小、明确的校验/覆盖状态，以及 K6 migration manifest/typed disposition 的 UI 只读摘要；不在 TUI 重写迁移算法 |

推荐状态分离（可按实际代码命名调整）：

- `Workspace`：只表示四个一级 Tab。
- 每个 Tab 的 `Route`：列表/详情/向导/结果与固定对象。
- `InspectView`：概览/结构/布局/扇区；与 PaneFocus 分离。
- `InputContext`：浏览、字段、搜索、命令、确认，不通过某个页面 Option 是否存在猜测模式。
- `OperationContext`：固定源/目标、计划、OperationId、结果，不借用当前列表 selection。
- `ActionDescriptor`：动作名、键位、作用范围、启用条件、禁用原因、是否危险、底栏优先级；帮助/更多/页脚共用。

只保留一套动作语义。动作描述数据可以在 dispatch 中驱动测试，但不要为了数据驱动引入庞大插件系统。

### 12.3 必须保持的业务与安全边界

- 输入/日志继续消毒；worker 不直接写终端；旧代次任务不覆盖新对象。
- 不能通过降低测试覆盖或删除安全断言来使 UI 测试通过。旧键位契约应替换为本规格的新断言，并补反向测试。

## 13. 验收清单

### A. 导航与输入（硬性门禁）

- [ ] 从设备开始连续 8 次 Tab 得到 `制盘→备份→检查→设备` 两轮；Shift-Tab 得到反序。
- [ ] 制盘 SelectDisk/Menu/Form/Review/Result、检查各视图、备份详情均执行同一一级导航规则。
- [ ] 只读加载中可切页；完成结果只更新原操作上下文。关键操作禁切时必须显示原因。
- [ ] Tab 切走再回来，选择、滚动、筛选、检查节点、草稿保持。
- [ ] 从列表 Enter 恒进详情，40/60/80/120/160 列行为一致；p 专门进制盘。
- [ ] 搜索、命令、姓名、路径、密码输入 `q` 不退出；`j/k/i/m/?/数字` 都按输入模式成为文本。
- [ ] Esc 逐层返回；跨页检查回到准确来源；一级切换不会生成循环返回栈。
- [ ] 事件分派集成测试覆盖以上行为，不能只测 KeyMapper 返回了正确枚举。

### B. 内容与视觉

- [ ] 所有可交互 Table 渲染点都使用统一 TableInteractionState / active-column layout；不得存在页面私有 h/l 横滚实现。
- [ ] 所有表格统一满足 j/k 行、h/l 激活列、</> 移动整列、0/$ 首尾列、H/L 2-cell 连续视口、s 排序、S 默认顺序；帮助、标题、页脚与真实分派一致。
- [ ] 激活列在可用宽度内完整展开且不显示省略号；排序后仍选中同一业务对象，Enter/删除/恢复/制盘等动作不得落到相邻对象。
- [ ] 页面正文、表格标题、页脚不重复展示快捷键清单；同一动作底栏只出现一次。
- [ ] 设备 1 条、0 条、多条都无固定半屏空表和冗余统计卡。
- [ ] 备份默认先看到时间、归属、容量、盘型、校验；长文件名不占首屏主列。
- [ ] 普通浏览备份不显示对隐藏选盘的“硬件冲突”；显式比较时完整显示目标。
- [ ] 校验通过、范围部分、关系不匹配可同时正确展示；不会被合并成一个健康结论。
- [ ] 无 Manifest/未知类型/未支持文件系统/锁定/未采集都按真实状态展示。
- [ ] 完整路径和 SHA 能在详情查看，中文长部门不挤掉关键状态。
- [ ] 所有基准尺寸无 panic、重叠、越界、不可达焦点；极小屏仍有安全退出路径。
- [ ] 密码不进入截图夹具、日志和复制摘要；视觉检查使用合成身份数据。

### C. 流程与安全

- [ ] 从备份页可直接选择源盘创建备份；恢复向导内部选择目标。
- [ ] 草稿设备拔出后，不会改选相邻盘继续；重新插入同编号不同介质需重新确认身份。
- [ ] 编辑参数、更换模式/目标后旧计划失效；旧异步计划结果不能重新启用旧计划。
- [ ] 制盘前保存成功回到原流程；失败不能悄悄跳过。
- [ ] 备份排序/过滤后删除对象仍固定；隐藏勾选明确提示；保留底线与摘要复核继续生效。
- [ ] 非精确 YES 不执行；q/Tab/Enter 的组合不能绕开安全确认。
- [ ] 写盘关键阶段退出按安全检查点完成；终端异常恢复不遗弃 worker。
- [ ] 校验失败、部分删除、制盘成功但格式化失败、回滚失败都不是总的绿色成功。
- [ ] Metadata/Deep 文案不承诺完整普通文件备份或原子快照。

### D. K6 文件级无损迁移

- [ ] 选择 Plain 目标时仍执行来源密码域探测；EDP→Plain 可在 P3 输入并按 `v` 验证来源密码。
- [ ] 来源密码字段按源盘真实密码域和本次读取需求显示；Unknown 不伪装为“无密码”。
- [ ] Plain→EDP 不显示不存在的 EDP 来源密码域；EDP→EDP 明确区分来源密码与目标密码。
- [ ] P4 只有真实 `Migrate` 时显示 `K6 文件级无损迁移`，文件数/字节数与 migration manifest 一致。
- [ ] “重建目标文件系统 + K6 迁移”不会被简化成单独“重建”。
- [ ] planning 展示 Probe/Inventory/Stage/Build/Verify/Ready 等类型化真实阶段；无总量时不伪造百分比。
- [ ] P5/P6/P7 持续显示 K6 规模、阶段和最终读回结果，不在计划页后丢失上下文。
- [ ] 修改目标、模式、来源密码或其它影响迁移的参数后，旧 plan/summary/generation 立即失效。
- [ ] K6 UI 不提供绕过来源密码验证、事务写入、readback、rollback 或系统盘保护的入口。
- [ ] 真实授权测试盘完成 TUI EDP→Plain→EDP round-trip；全量文件 SHA-256 与迁移前基线一致。

### E. 验证与交付

1. 日常使用 `scripts/test-fast.sh`；所有修改必须通过相关 TUI 及安全契约测试。
2. 本轮涉及广泛状态与导航重构，结束前运行 `python3 scripts/test-full.py --profile full`，使用至少 600 秒预算；持续观察同一进程到退出，不重启重复跑。
3. 不把 `cargo check --all-targets` 与 `cargo test --all-targets` 串在一个 120 秒同步调用；普通验证不启用 `ci-virtual-disk`。
4. 真实硬件验收单独报告，本轮截图/导航测试不需要真实写盘。没有执行的硬件验证不得记为通过。
5. 使用 TestBackend/合成数据截图或快照覆盖上述尺寸和状态；对关键布局人工看渲染结果，不能仅搜索字符串存在。
6. 提交前 `cargo fmt --all`，安装并使用仓库 hook，不绕过；合并/发布前保留 CI fmt 检查。
7. 若用户随后要求安装试用版，用 `scripts/install-local.sh` 安装至 `~/.local/bin/edpcli`，验证交互 shell 路径与二进制 SHA-256 一致。
8. 交付源代码、验证结果、关键页面前后截图、功能入口对照、未完成项。不得以“界面更简洁”代替完整验收。
