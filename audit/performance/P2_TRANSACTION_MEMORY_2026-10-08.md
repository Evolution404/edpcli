# P2 磁盘事务内存与 I/O 优化：首批收口

日期：2026-10-08。测试平台：Mac 本机、Rust Release、虚拟文件介质。**没有读取或写入真实 U 盘**。

## 问题、实现与边界

原通用事务执行器为每个 touched LBA 分别分配 512B `Vec<u8>`，并放进 `BTreeMap<u32, Vec<u8>>` 作为回滚镜像。虽然前次已去除“待写计划扇区内容的全量复制”，原始数据镜像仍有 N 次数据内存分配 + 树节点开销。设备端 `read_sector` 必须返回 `Vec<u8>`，且同步读回也逐扇分配。

本轮变更：

1. `readback_order` 已按 LBA 排序，回滚镜像用一次预留的 `Vec<[u8;512]>` 按同一索引连续存储。回滚时二分查找 LBA，无需重复保存键、树节点和逐扇数据堆分配。内存预留失败时在实际写盘**之前**拒绝执行。
2. `SectorDev::read_sector_into` 提供向调用方固定 512B 缓冲区读取的默认实现；已有模拟设备、故障注入和第三方 SectorDev 实现无需改动，仍通过既有 `read_sector`。只有 `FileDev` 覆盖它，直接填充固定缓冲区，无需逐扇新建临时 Vec。
3. 事务镜像与读回通过 `read_sector_into`；不修改预检同步、所有 touched 扇区的镜像保护、数据→协议元数据→LBA0 提交顺序、写后同步、逐扇读回，以及最多三次回滚/读回验证。异常或短扇区在正式写盘前拒绝事务。
4. `ordered_lbas` 利用 BTreeMap 已有的 LBA 有序性，按三个 stage 顺序扫描，去除原先需比较排序的中间 `(stage,lba)` 元组数组。

**本阶段未变更：** 物理 I/O 的单扇区写入、分区格式化镜像形态、保守 8 倍资源预算、授权与实体盘保护。尚未批准连续扇区批量写入或流式格式化，防止改变失败回滚的正确性边界。

## 32,768 / 65,536 扇区内存对比

| 指标 | 改动前单次 | 改动后 5 次测试中位数 | 改变 |
|---|---:|---:|---:|
| 32,768 扇区事务峰值增量 | 18,736 KiB | 16,720 KiB | -2,016 KiB（-10.8%） |
| 65,536 扇区事务峰值增量 | 37,392 KiB | 33,360 KiB | -4,032 KiB（-10.8%） |
| 32,768 扇区事务耗时 | 150.8ms | 150.8ms | 不足以得出性能提升结论 |
| 65,536 扇区事务耗时 | 279.6ms | 312.7ms | 不足以得出性能提升结论 |

最大 RSS 增量为各子进程的历史高水位差，不是孤立镜像对象的精确内存占用；改动前仅一次测量，不能将耗时差异视为严谨的吞吐回归。真实 USB 的读写、同步与热插拔行为另行验证。

## 安全回归

新测试覆盖：非连续 LBA 与 MBR 最后提交时的故障回滚恢复；镜像读取返回 511 字节时全部拒写；读取第二个镜像扇区故障时拒写；文件设备固定缓冲区读取与传统读取一致，以及超出文件长度的 EOF；原有写前 sync、写后 sync、回滚失败报错、回调 panic 隔离与逐扇读回测试维持不变。
