# S1：真实 FAT16/FAT32/exFAT 元数据及 SM4 格式化剖析

**日期与范围**：2026-10-08，Mac release 模式，`cd52332` 起始。样本来自项目生产 FAT16/FAT32/exFAT 格式化驱动，SM4 使用真实 `EdpSm4Transform`。**只对临时普通文件镜像写入；未读写实体 U 盘。**

## 重现

```sh
uv run --locked python scripts/benchmark-s1-real-format.py --samples 3
```

保存的逐次读数：`audit/performance/s1-real-format-20261008.json`。每一种有效几何×明文或 SM4 组合均以新进程运行 3 次，报告中为 3 次中位数。步骤包括真实元数据构建、实际 SM4 物理扇区变换、文件系统驱动元数据验证、同一事务执行器写入与逐扇读回。在最后一个已触及元数据 LBA 之后截断/创建临时镜像文件，**不初始化全部分区数据区**，可避免巨型稀疏整盘文件的非必要消耗。故仅衡量项目当前的空文件系统**稀疏元数据写入**，不是整个新卷的清零吞吐或真实物理存储设备性能。

## 实测：各卷大小的代表性中位数

| FS / 卷扇区数 (512B) | 有效元数据扇区 | 构建 ms | SM4 转换 ms | 事务 ms | 峰值 RSS KiB（SM4） |
|---|---:|---:|---:|---:|---:|
| FAT16 / 20,417 | 193 | 0.12 | 3.95 | 8.10 | 6,080 |
| FAT16 / 262,144 | 545 | 0.29 | 8.75 | 9.01 | 6,816 |
| FAT16 / 1,048,576 | 545 | 0.26 | 7.80 | 8.62 | 6,864 |
| FAT32 / 262,144 | 4,101 | 1.55 | 53.87 | 10.85 | 14,784 |
| FAT32 / 16,777,216 | 65,544 | 26.33 | 836.20 | 42.39 | 151,424 |
| FAT32 / 67,108,864 | 65,556 | 26.48 | 840.65 | 42.33 | 151,440 |
| exFAT / 32,768 | 80 | 0.07 | 1.12 | 9.27 | 5,792 |
| exFAT / 524,288 | 328 | 0.19 | 4.78 | 9.64 | 6,432 |
| exFAT / 16,777,216 | 2,264 | 0.97 | 29.44 | 9.43 | 11,696 |
| exFAT / 1,000,000,000 | 32,077 | 14.37 | 409.78 | 27.82 | 72,208 |

单机普通文件 I/O 受缓存及文件分配影响，特别是 8–11 ms 的小规模同步开销。RSS 是整个进程最高驻留内存，**不能**解释为该步独占内存；阶段前/后高水位读数、预算估算及单次原始样本见 JSON。现行 `working_payload_bytes = payload_bytes * 8` 仍是保守预算，不按此报告立即降低系数。

## 观察与合理性结论

1. **P2.4 全面流式重构暂缓**。FAT16 和 exFAT 实际稀疏元数据生成成本很低；在当前验证范围内，不能仅凭合成负载推断流式接口会显著改善体验。
2. **优先评估 SM4 变换算法与冗余分配**。例如 FAT32 65,544 扇区产生约 32 MiB 元数据，构建约 26ms，SM4 加密约 836ms；exFAT 1,000,000,000 扇区构建约 14ms，SM4 约 410ms。应先剖析 CPU、避免重复生成明文镜像、复用变换结果；保持密钥与协议兼容性，绝不为提速采用有安全风险的加密变体。
3. **明确仍未覆盖的组合**：多分区规划累计峰值、真实恢复后加密重初始化混合元数据+数据提交、实际 USB 同步和断电、磁盘身份变化与生产 TUI 操作。必须单独测试才能修改这些路径。
4. 当前预算保护以及 preflight→全部 touched 镜像→Data/Metadata/Commit→sync→逐扇读回→回滚机制均保持；**没有扩大支持范围或改变实体介质批量 I/O 策略**。
