# P2 有界连续 I/O：仅普通文件镜像启用

日期：2026-10-08。依据：同一 Mac、Rust release、全新独立临时文件镜像，5 轮取中位数。未操作真实 U 盘。

## 新执行策略与硬性安全边界

`SectorDev` 添加默认 `max_contiguous_sectors() = 1`、`read_contiguous_sectors_into` 和 `write_contiguous_sectors`。所有已有实现保留原先逐扇区行为；只有 `FileDev` 针对**非 raw 路径**返回 128 扇区上限。即使直接调用 `FileDev` 的连续接口，raw 路径仍退化为逐扇区调用，不能绕过这条边界。跨平台 raw 路径由现有平台适配层判断，不引入硬编码路径。

统一事务引擎按既有读回/写入 LBA 顺序形成严格连续的有界区段，每区段最多 128 扇区 / 64 KiB。原来的写前同步、全 touched 镜像、写入顺序（Data→Metadata→LBA0）、写后同步、逐扇内容校验、回滚的同步和读回检查全部保留。不连续的 LBA 绝不穿越；每个成功的批次仍发出每扇区的进度事件，失败批次不伪报已完成的扇区。每轮内存批量缓冲区最多 64KiB。

一个 batched `write_all` 可能已部分写入介质才报错；与单扇区失败一致，事务用**全部 touched 扇区**的镜像回滚，而不依赖不可信的“已成功写多少”信息。任何缓冲区读回不一致按精确 LBA 报错并触发回滚。硬件 raw 设备仍走旧逐扇路径，本轮不宣称其吞吐变化。

## 五轮独立进程的文件事务性能对照

执行：

```sh
uv run --locked python scripts/benchmark-p2.py --samples 5
```

两组不可变原始快照：

- `audit/performance/p2-before-batched-io-20261008.json`
- `audit/performance/p2-after-batched-io-20261008.json`

| 测试 | 原逐扇扇区 I/O 中位数 | 普通文件批量 I/O 中位数 | 加速比例 |
|---|---:|---:|---:|
| 32,768 扇区（16 MiB）事务 | 130.97 ms | 31.43 ms | 4.17× |
| 65,536 扇区（32 MiB）事务 | 250.04 ms | 45.78 ms | 5.46× |
| 32,768 扇区事务峰值 RSS 增量 | 16,720 KiB | 16,784 KiB | +64 KiB |
| 65,536 扇区事务峰值 RSS 增量 | 33,360 KiB | 33,424 KiB | +64 KiB |

备注：事务包含写前 sync、镜像读取、数据与 LBA0 写入、写后 sync、全部读回；使用 Mac 系统文件缓存和普通文件，不模拟实际 USB 控制器、总线带宽、写保护和断电模式。每次批量 I/O 的上限为 64KiB；额外峰值 +64KiB 与这一预算相符，但 RSS 高水位不是精确堆分配测量。

## 压力与故障测试

- 131,072 扇区（64 MiB）事务的单次文件镜像测试成功；约 79.6ms，峰值增量 66,704KiB。原始稀疏格式化数据借用事务 64MiB 单次成功；约 95.5ms。
- 自定义 mock 显式启用 4 扇区 batching，测试成功事务的阶段排序/同步次数和每扇区进度事件。
- 注入批量写过程中“第一扇区已写、随后抛错”，完整回滚所有计划扇区，LBA0 仍最后恢复。
- 注入批量读回特定 LBA 的数据错误，定位到精确 LBA 并触发完整回滚。
- 用实际文件描述符指向临时普通文件，同时将其分类路径替换为 raw 形式，验证明确禁用合并 I/O（而不真正打开任何 raw 设备）。

## 仍需验证与下一阶段

本轮不能替代真 USB 的同步落盘语义、物理断连、重插挂载、USB BOT/UASP 性能评估或写保护失效验证。开启原始设备批量写入需要独立风险评审、额外故障注入、介质身份再确认和明确用户授权；不由本轮自动开启。大容量真实空文件系统构造仍需在预算与流式驱动设计方面继续研究。
