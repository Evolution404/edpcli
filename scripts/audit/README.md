# 全仓冗余扫描

在仓库根目录执行 `make audit`，或直接执行：

```bash
uv run --locked python scripts/audit-redundancy.py --check
```

Python 入口调用已注册的 Rust `audit-redundancy` example，用 `syn` 读取全部 Rust AST。首次运行会编译工具，后续复用 Cargo 缓存；只生成报告，不操作设备、不删除文件。需要仓库现有 Rust 工具链与 Python 3.11+，无额外安装步骤。

`git ls-files --cached --others --exclude-standard` 提供完整当前文件集，覆盖未提交的新文件，跳过已删除路径及忽略的用户数据、日志、构建缓存。Cargo 元数据给出全部目标入口，模块图遍历所有 `cfg` 分支、内联模块及 `#[path]` 文件。`cfg(test)` 子模块的文件消费者按测试归类。

默认报告为 `target/redundancy-audit/report.md` 和 `report.json`，可用 `--output /path/to/report-directory` 改变报告位置。`--check` 对确认问题返回 1，工具执行失败返回 2；待核查候选不会导致门禁失败。

## 规则扩展约定

[规则表](redundancy-rules.json) 登记每一种发现类型。[Python 入口](../audit-redundancy.py) 对所有文件执行全部规则；不采用仅变更文件模式。

1. 发现新的冗余类型时，登记规则 ID、类型、说明及必要参数；规则须覆盖同类问题，不能只匹配首次发现的一个文件。
2. 在通用检测器实现该类型。代码语义需要新的 AST 事实时，扩展 [Rust 检测器](redundancy_scan.rs)。未实现的规则必须报错，不能静默跳过。
3. 在现有工程脚本测试或检测器 Rust 单元测试中补充行为回归，覆盖漏扫、条件分支和误判边界。
4. 重新执行一键命令，核查整个报告。确认已过时的实现/文件可移除，仍有效的安全接口、历史介质兼容、手动工具及回归证据要记录保留依据。
5. 已确认退役的入口加入规则表的退役清单，使同类旧入口回流能自动检出。名称存在冲突时应收窄规则范围。

## 检测边界

未注册源码、无人引用或仅测试引用的公开类型/常量声明、无人引用的公开接口、仅测试引用的接口或整个模块、被忽略的参数、单次转发包装及未被提及的脚本均为核查候选。它们可能是公开安全构造能力、平台钩子或独立手动工具。工具不能据此自动删除。

引用按 AST 名称保守统计，支持导入别名并检查宏中的标识符；忽略注释、字符串中的伪调用和单纯重导出。整模块规则同时核对函数与类型等声明，并保守排除含公开重导出或 trait 实现的模块。声明规则还会统计类型签名及 `impl` 中的类型路径，引用计数不能证明运行时可达性。宏不展开，也不能证明跨模块同名方法、运行时注册及外部消费者的完整调用关系。编译器与行为测试仍是清理后的必要验证。

文档检测覆盖本地 Markdown 链接（不验证锚点）、不存在的 Cargo `--test` 目标和完全相同的重复文档。重复内容仍需核查职责；历史设计是否仍有效需要对照实际入口与现行契约，不能仅凭日期判定。
